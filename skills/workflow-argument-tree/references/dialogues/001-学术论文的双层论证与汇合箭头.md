## 原始困惑

> 用户：OK。我们刚才聊到，学术论文是「双层论证」了，对吧？所以「论效题」只有一个第一级大箭头，学术论文应该是有两个一级大箭头吗？还是怎样理解这两个箭头的关系？

## 当时回答

> Codex：对，我们刚才已经把学术论文理解成“**双层论证**”了。但我会稍微修正一句：不是简单地说“学术论文有两个并列的一级大箭头”，而是更像：
>
> ```text
> 外层大箭头：为什么这篇研究值得做、值得发表
> 内层大箭头：作者关于 X -> Y 的核心发现是否成立
> ```
>
> 这两个箭头不是并列的两篇文章，而是**嵌套 + 汇合**的关系。
>
> 可以这样画：
>
> ```text
> 外层论证：
> 现有研究没有充分解释 X 如何影响 Y
> + 这个问题理论/现实上重要
> + 本文相对既有研究有差异
> → 研究这个问题有意义
> → 本文有潜在贡献
>
> 内层论证：
> 理论机制
> + 变量测量
> + 数据样本
> + 识别策略
> + 实证结果
> + 机制/稳健性
> → X 如何影响 Y 的发现成立
>
> 二者汇合：
> 研究问题值得做
> + 本文把它做成立了
> → 本文贡献成立 / 值得发表
> ```
>
> 所以如果用“大箭头”来说，学术论文至少有三个层次：
>
> ```text
> 第一支箭头：gap / significance -> 研究正当性
> 第二支箭头：evidence / method / results -> 核心发现成立
> 最终汇合箭头：研究正当性 + 核心发现成立 -> 贡献成立
> ```
>
> 论效题通常更压缩，材料里往往只有一个总论点：
>
> ```text
> A/B/C 若干论据 -> 总结论
> ```
>
> 但学术论文更复杂，因为它既要证明：
>
> ```text
> 我为什么要研究这个问题
> ```
>
> 又要证明：
>
> ```text
> 我真的把这个问题研究出来了
> ```
>
> 这两个缺一不可。
>
> 一个非常实用的审稿判断是：
>
> ```text
> gap 成立，但结果/识别不成立
> → 题目可能重要，但这篇没做成。
>
> 结果可能成立，但 gap 不成立
> → 发现可能是真的，但贡献被夸大。
>
> gap 和结果都成立，但二者没接上
> → 做出了一些结果，但没有真正回应作者声称的文献缺口。
>
> gap、结果、贡献三者都接上
> → 论文主论证链才比较稳。
> ```
>
> 所以我建议我们把学术论文的论证结构固定成：
>
> ```text
> 论文总贡献论证
> ├── 外层：研究正当性论证
> │   └── gap / importance / novelty -> worth studying
> ├── 内层：核心发现成立论证
> │   └── theory / data / identification / results -> finding holds
> └── 汇合：贡献成立论证
>     └── worth studying + finding holds + actually answers gap -> contribution holds
> ```
>
> 一句话：  
> **论效题通常是一条压缩总箭头；学术论文是两条一级支撑箭头汇合到“贡献成立”这一最终大箭头。**

## 共同发现

学术论文不是简单拥有两个并列的一级大箭头，而是具有“外层研究正当性论证”和“内层核心发现成立论证”，二者在“贡献成立 / 值得发表”处汇合。

这使审稿不应只按文献、方法、变量、结果等模块横切，而应先还原：

```text
研究是否值得做
+ 作者是否真的做成立
+ 本文是否真正回应了所声称的 gap
-> 贡献是否成立
```

## 候选方法论命题

```text
如果以后审读学术论文，
应当先区分外层研究正当性论证、内层核心发现成立论证和最终贡献汇合论证，
因为 gap 成立、结果成立、贡献成立是三个相关但不同的判断。
```

## 可迁移规则草案

- 输入信号：
  - 用户询问论文贡献、gap、核心发现、审稿主轴或“论文到底在证明什么”。
  - 审稿过程中出现 gap 与实证结果、贡献声称之间接不上。
- 处理动作：
  - 先画三层论证结构：
    1. `gap / importance / novelty -> worth studying`
    2. `theory / data / identification / results -> finding holds`
    3. `worth studying + finding holds + actually answers gap -> contribution holds`
  - 对每个 major concern 标注它切断的是哪一层箭头。
- 输出要求：
  - 不把 gap 问题误写成识别问题；
  - 不把识别问题误写成贡献定位问题；
  - 必须说明该问题如何影响最终贡献成立。
- 验收标准：
  - 能解释四种情况：gap 成立但没做成、结果成立但 gap 不成立、gap 和结果没接上、gap/结果/贡献三者接上。
