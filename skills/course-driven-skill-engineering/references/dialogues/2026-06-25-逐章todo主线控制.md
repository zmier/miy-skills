# 逐章 TODO 主线控制

## 触发场域

SMK 实证资产定价学习项目进入逐章学习前，用户提出：每章不能随便讲，需要有主线，避免被临时问题带偏；可能需要知识点 TODO list。

## 用户原始问题

> 但是每章应该不能随便讲吧？我们得有个主线才行，这样能确保这章的知识点都讲到，而不会被我的问题带的过于发散和跑偏，对吧？比如可能需要落一个知识点的todo list？

## 共同发现

长期教材学习需要同时保留两种力量：

- 用户问题：暴露真实困惑，让学习不是机械读书；
- 章节 TODO：保证教材主线和核心知识点被覆盖。

只靠用户问题会发散；只靠章节目录会死板。更稳的结构是：

```text
学习单元 TODO
→ 每轮讲解绑定一个或多个 TODO
→ 用户问题归类为主线内、主线旁路或停车场
→ 学习单元结束前回查 TODO
```

## 候选原则

当学习对象是书籍章节、课程课时或一组连续知识点时，正式讲解前应建立 TODO 控制表，并为每个知识点写清：

- 知识点；
- 角色；
- 状态；
- 通过标准。

核心 TODO 未完成，不进入下一章或下一课时。
