# Textbook Learning Project Workflow

## 定位

本 reference 用于把一本教材、一本技术书、一本研究方法书或一套长课程，转成可持续推进、可记录、可练习、可迁移、可反哺 Skill 的学习项目。

它不是单次讲解协议，也不是单纯题库生成协议，而是承接整条学习工程链：

```text
选书与定位
→ 建项目承载共识
→ 技术拆书
→ 原书精读
→ 逐章 TODO 与学习档案
→ 项目语境迁移
→ 原子知识点覆盖表
→ 刷题诊断
→ 知识修复与卡片化
→ Skill / workflow 反哺
```

## 适用场景

- 用户从零开始学习一本较难教材；
- 用户希望把教材方法和自己的真实项目、数据、工作流或实盘经验结合；
- 教材学习会跨多轮对话，需要文档承载共识；
- 用户既想理解原书，又想用大模型、拆书工具、题库和知识卡片提高效率；
- 学习过程中产生可迁移的方法论，需要反哺 Skills 或 workflows。

## 项目承载

长期教材学习不应只停留在对话里。先建立项目承载层，用来保存共识、任务、输出、日志和验证。

推荐结构：

```text
PROJECT-章程.md
TASK-总-学习项目.md
tasks/
docs/
outputs/
logs/
final_outputs/
```

项目章程至少回答：

- 为什么学这本书；
- 它属于哪个上位知识体系；
- 第一轮学习范围是什么；
- 哪些内容只做索引，哪些内容要掌握；
- 如何和用户的真实项目或实践语境连接；
- 哪些产物会反哺 Skill / workflow。

## 选书定位与学习边界

正式学习前，先判断教材承担的角色：

| 角色 | 学习重点 |
|---|---|
| 方法框架书 | 学方法链、证据链、操作顺序和适用边界 |
| 案例库 | 学案例如何验证、迁移和反驳方法 |
| 工具书 | 建索引和查用入口，不必线性精读 |
| 领域入门书 | 建概念网络和主线地图 |
| 项目迁移书 | 把书中方法映射到用户数据、工具或工作流 |

如果教材有很多章节，第一轮应明确：

```text
第一轮必须掌握的章节
→ 第一轮只做索引的章节
→ 第二轮回收的章节
→ 可直接进入项目实验的接口
```

不要把“读完整本书”默认等同于“第一轮精读所有章节”。

## 技术拆书与原书精读

大模型拆书、PDF 抽取、book-to-skill、目录识别和结构摘要，适合作为导航和索引，不应替代原书精读。

推荐关系：

```text
技术拆书：快速获得目录、章节范围、关键词、方法链和候选重点
原书精读：确认概念、公式、例子、边界、作者论证和误读风险
学习档案：记录用户问题、Codex 讲解、最小复述和迁移判断
```

使用拆书工具时必须记录：

- 工具名称和版本；
- 输入材料；
- 输出路径；
- 抽取质量，例如目录是否识别、页数是否完整、公式/表格是否可靠；
- 结论边界：哪些可直接用，哪些必须回到原书核验。

## 逐章学习档案

每章建立一个学习档案，用来保存学习过程，而不是只保存总结。

推荐结构：

```text
课前导航
→ 知识点 TODO
→ 用户问题
→ Codex 讲解
→ 最小复述
→ 项目语境迁移
→ 卡片候选
→ 停车场
→ 下一章连接
```

学习档案的价值在于保留“用户怎么理解、哪里卡住、怎么被讲通”。这类信息不适合直接写进通用 Skill，但很适合后续生成知识修复卡、方法卡片和教学风格偏好。

## 主线控制

逐章学习时，先建立学习单元 TODO，再回答问题。

问题分流：

| 类型 | 处理 |
|---|---|
| 主线内 | 挂到当前 TODO，推进讲解 |
| 主线旁路 | 简短展开，标注后续回收位置 |
| 停车场 | 记录，不打断当前章 |
| 反哺候选 | 写入 TASK log 或 dialogue insight |

推荐讲解风格：

```text
直觉问题
→ 最小公式、伪代码或结构图
→ 每个参数/步骤的含义
→ 结果变化的可能解释
→ 回到用户项目语境
→ 标注后续章节或 TASK 回收位置
```

## 项目语境迁移

当用户希望把教材方法用到真实项目时，先区分：

```text
原书结论是否可迁移
方法链是否可迁移
变量口径是否可迁移
数据覆盖是否可迁移
交易或业务结论是否可迁移
```

通常更稳的做法是：

- 先迁移方法，不直接迁移结论；
- 先用用户数据复现方法链，再讨论结论；
- 把样本口径、变量可得性、控制变量、缺失值、极端值处理等边界写进项目文档；
- 若某个讨论暴露出论文论证箭头问题，交给对应 argument-validity workflow 或 domain adapter，而不是塞进 course-driven 主流程。

## 刷题学习分支

当用户希望更快暴露盲点时，可以从逐章讲解切换到刷题学习法。

切换条件：

- 已有章节边界和主线 TODO；
- 有可靠原文或抽取文本；
- 用户希望覆盖尽可能完整的知识点；
- 已接受模型生成题只作为诊断题，不伪装成真题。

此时读取 `atomized-reading-to-quiz-workflow.md`，执行：

```text
逐章边界
→ 逐段读取
→ 段落功能分类
→ 原子知识点覆盖表
→ 单选题优先
→ 题库校验
→ 错题回流
```

刷题学习不是替代原书，而是把原书学习结果变成检测器。

## 知识修复与卡片化

刷题、复述或项目实验暴露的薄弱点，先回到项目/课程层修复。

推荐分层：

| 层级 | 放什么 |
|---|---|
| 项目/课程层 | 错题、薄弱点、章节修复、项目语境 |
| Zettelkasten | 已讲清楚、跨章节可复用的概念、方法和关系 |
| MOC / dashboard | 章节、题库、修复卡、永久卡片之间的导航 |

不要把每个题目、每次问答、每个教材细节都升级成永久卡片。

## Skill / Workflow 反哺

教材学习项目中可能出现三类反哺：

| 类型 | 去向 |
|---|---|
| 学习治理方法 | `course-driven-skill-engineering` reference |
| 领域论证或证据链问题 | 对应 `workflow-argument-validity` adapter |
| 稳定概念或方法卡 | `simon-learning-card-builder` 或知识库 |

反哺前要区分：

```text
项目个案事实
→ 用户个人理解路径
→ 可复用学习结构
→ 可迁移领域方法
→ 已验证 workflow 规则
```

未经多场景验证的内容，标记为：

```text
structural-green / forward-test-pending
```

## 最小完成标准

一个教材学习项目至少应满足：

- 有项目承载层，而不是只散落在对话里；
- 有第一轮学习范围和章节边界；
- 技术拆书产物与原书精读边界清楚；
- 每章有 TODO 和学习档案；
- 用户问题被分流为主线内、主线旁路或停车场；
- 若进入刷题学习，先有 atom 覆盖表再生成正式题库；
- 错题和薄弱点能回流到章节档案或知识修复；
- Skill / workflow 反哺有 provenance，不污染具体项目内容。

## 迁移状态

当前规则来自 SMK 实证资产定价学习项目、小红书学习提示词样本、book-to-skill 调研和本地刷题系统实践，状态为：

```text
structural-green / forward-test-pending
```

它已经能指导类似教材学习项目的结构化落盘，但尚未在多个不同学科项目中完成 forward-test。
