# 盲做优先协议

## 信息分层

### 可在 blind 阶段读取

- 课程单元名称与学习目标；
- 靶场、样本、输入输出和授权说明；
- 环境安装说明与安全限制；
- 为定位原始材料所需的文件清单；
- 经审计不泄漏解法的课程目录或知识地图标题。

### 默认冻结

- 教师的步骤顺序；
- 关键函数、地址、算法、Key、盐和最终答案；
- 完整 Hook 脚本、复现代码与成功请求；
- 直接给出根因的课堂结论。

知识地图出现以下内容时也视为泄漏：

- 具体算法或模式，如“双轮加盐摘要”“AES-CBC”；
- Key、IV、盐或参数的来源；
- 关键 Hook 点、函数名、偏移或加载时机；
- 完整工具顺序，如“先监听 dlopen，再安装 Native Hook”；
- 已经解释数据形态的结论，如“MD5 原始摘要作为 Key”。

## 独立性等级

- `strict-blind`：未接触任何解法信息。
- `limited-blind`：只知道目标和必要环境，少量概念暴露不决定路线。
- `prior-exposed`：已知关键算法、工具或路线，但实现与证据仍自行完成。
- `assisted`：复现过程中主动读取教师步骤或代码解决阻塞。

这些等级描述发现过程，不影响运行证据本身是否真实，但会影响“独立发现”的声明强度。

## 解冻门

满足任一条件可解冻：

1. 独立路线达到预设 Green；
2. 同一阻塞已完成至少三轮有区分度的实验，且没有合理新实验；
3. 继续盲做有安全风险、不可逆副作用或明显不经济；
4. 当前目标明确是学习教师工具操作，而非检验独立求解能力。

提前解冻时必须记录：

- 阻塞点；
- 已尝试实验；
- 解冻的最小范围；
- 教师信息从此只能作为 `confirmatory` 或 `assisted`，不能再标为完全独立证据。

## 防泄漏

- 不在 blind TASK 中引用教师结论文件。
- 不把教师代码复制为自己的实现后声称复现。
- 对同一 Agent 已读取的教师答案，不能再声称执行严格盲测；应标记 `assisted comparison`，后续用新案例做真正 forward-test。
