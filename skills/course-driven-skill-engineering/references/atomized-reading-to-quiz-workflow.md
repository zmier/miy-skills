# Atomized Reading To Quiz Workflow

## 定位

本 reference 用于把教材、课程讲义、论文教材章节或长篇学习材料，拆成可覆盖、可检测、可回流修复的原子知识点，并进一步接入刷题学习法。

它回答的问题不是“怎么讲这一章”，而是：

```text
如何逐段读原文
→ 判断哪些内容值得抽成原子知识点
→ 建立覆盖表
→ 生成低摩擦题目
→ 用刷题结果反向修复学习档案和知识卡片
```

## 适用场景

- 用户希望从精读切换到刷题学习；
- 教材章节知识点密集，不能只靠自由问答推进；
- 用户要求“尽量穷尽知识点”，而不是象征性生成少量题；
- 需要把题库结果回流到章节档案、知识修复、Zettelkasten 或 MOC；
- 没有现成真题或章节题，需要基于教材和项目拆解生成模型题。

## 总流程

```text
确定章节边界
→ 逐段读取原文或可靠抽取文本
→ 标注段落功能
→ 判断是否产生原子知识点
→ 写入原子知识点覆盖表
→ 为每个核心 atom 配题
→ 校验题库
→ 刷题暴露薄弱点
→ 回流章节档案、知识修复和卡片候选
```

## 逐段读取协议

逐段读不是“每段都抽一个知识点”。先判断段落功能，再决定是否抽取。

推荐段落功能标签：

| 标签 | 含义 | 抽取倾向 |
|---|---|---|
| `definition` | 引入概念、变量、术语、对象 | 通常抽 |
| `method-step` | 给出方法步骤、计算过程、操作顺序 | 通常抽 |
| `tradeoff-boundary` | 说明取舍、前提、边界或失败模式 | 通常抽 |
| `misread-risk` | 容易混淆、误解或错误迁移的点 | 通常抽，并优先出题 |
| `example` | 例子、应用场景、局部说明 | 视是否承载新知识而定 |
| `bridge` | 章节过渡、承上启下 | 一般不抽，除非定义主线结构 |
| `repetition` | 重复前文、修辞性强调 | 一般不抽 |
| `citation-footnote` | 来源、脚注、文献说明 | 一般不抽，除非影响证据边界 |

每段至少问五个判断问题：

```text
1. 是否引入一个新概念？
2. 是否给出一个可执行的方法动作？
3. 是否说明一个取舍、边界或适用条件？
4. 是否暴露一个常见误读风险？
5. 是否能设计出一道有明确正确答案的检测题？
```

至少命中 1-4 中一项，并且第 5 项成立，才优先进入原子知识点覆盖表。

## 原子知识点标准

一个 atom 应满足：

- 只检测一个核心判断；
- 能被一道低摩擦题目检测；
- 有明确的正确/错误边界；
- 能回链到章节、段落、公式、表格、例子或项目讨论；
- 不把两个独立知识点塞进同一个 atom。

不合格 atom 示例：

```text
解释 Fama-MacBeth 回归并比较组合排序。
```

更合格的拆法：

```text
Fama-MacBeth 第一阶段每期做横截面回归。
Fama-MacBeth 第二阶段对时间序列系数取均值并检验。
组合排序更适合展示单变量或少量维度的收益差异。
Fama-MacBeth 更适合在多控制变量下估计边际解释力。
```

## 覆盖表字段

正式题库生成前，先建立覆盖表。推荐字段：

| 字段 | 含义 |
|---|---|
| `chapter` | 章节 |
| `section` | 小节或段落簇 |
| `atom_id` | 稳定编号 |
| `atomic_knowledge` | 原子知识点 |
| `type` | `definition / method / boundary / contrast / application / misread-risk` |
| `priority` | `core / support / advanced / defer` |
| `question_count_target` | 目标题量 |
| `question_style` | `recognition / contrast / scenario / formula-intuition` |
| `source_anchor` | 原文、抽取文本、章节档案或讨论记录锚点 |
| `status` | `draft / checked / questioned / deferred / banked` |

题量按知识密度和风险决定，不按章节机械平均。

## 题库化规则

当学习者对知识点还陌生时，先用低摩擦题型建立识别能力。

默认顺序：

```text
单选题
→ 多选或填空
→ 简答或最小复述
→ 场景题或综合题
```

模型生成题必须标注来源类型，不得伪装成真题。

推荐配题原则：

- 每个 `core` atom 至少 1 道单选题；
- `misread-risk` 至少 1 道对比题；
- `application` 至少 1 道场景题；
- 方法密集章节可以明显高于其他章节；
- 题目解析要说明“考的是哪个 atom”，而不是只解释选项。

### 禁止脚本批量生成题目内容

覆盖表、字段校验、重复检测、HTML 构建和错题统计可以脚本化，但题目内容本身不得由模板脚本批量生成。

这里的“题目内容”包括：

- 题干；
- 正确选项；
- 干扰项；
- 解析；
- 题目检测目标与 atom 的映射说明。

原因：

- 好题不是把 atom 改写成一个问题，而是判断学习者最可能在哪里误解；
- 干扰项必须来自真实误概念、混淆边界或迁移误用，不能只是泛泛的错误话术；
- 解析必须完成微型补课，而不是重复正确答案；
- 同一个 atom 的多道题应分别检测定义识别、概念边界、场景迁移、反模式识别或公式直觉，不能靠模板替换制造“题量”；
- 对初学者而言，题目会塑造注意力，低质量批量题会让学习者误以为自己掌握了其实没有掌握的概念。

允许使用脚本的范围：

- 从覆盖表读取 atom 并生成“待编题清单”；
- 检查每个 atom 是否已经有题；
- 校验 JSON schema；
- 检查重复题干、重复 ID、缺失字段；
- 构建 HTML；
- 汇总错题和薄弱 atom。

不允许使用脚本的范围：

- 自动把 atom 改写成题干；
- 自动生成正确选项或干扰项；
- 自动批量生成解析；
- 自动把 1 个模板循环扩展成多道“看似不同”的题；
- 在未经逐题人工审阅、修改和确认前，把脚本生成题标为正式题库。

### 手工编题认知原则

每一道题在进入正式题库前，必须经过人工权衡，并至少检查以下问题：

| 检查项 | 编题要求 |
|---|---|
| 单一检测目标 | 一题只检测一个 atom，不把两个独立判断塞进同一题 |
| 认知负荷 | 题干保持短而清楚，避免无关信息消耗工作记忆 |
| 干扰项诊断性 | 错误选项应对应一种可命名的误解，而不是随便编的错话 |
| 近迁移 | 至少部分题把概念放回教材方法或 A 股研究场景 |
| 反模式识别 | 对高风险 atom，要考“哪些做法看似合理但其实错” |
| 边界意识 | 解析说明适用条件、不能推出什么、和相邻概念的区别 |
| 生成效应 | 题目应促使学习者主动检索或辨析，而不是只做字面匹配 |
| 间隔复习 | 同一 atom 多题时，题型和角度应错开，支持后续错题回炉 |
| 误概念修复 | 解析优先修复导致错误的概念模型，而不是只宣布答案 |
| 学习回流 | 每题保留 `atomId`，便于错题回到章节档案、修复卡和后续讲解 |

推荐的手工编题顺序：

```text
读取 atom 与原文锚点
→ 写出“这题到底要抓住的误解”
→ 设计题干
→ 先写正确答案边界
→ 写 3 个有诊断价值的干扰项
→ 写微型补课式解析
→ 检查是否一题多考或答案歧义
→ 标注 atomId、sourceAnchor、difficulty、questionStyle
→ 进入 schema 校验和人工抽查
```

正式题库的题量可以分批完成。宁可每批少而精，也不要用脚本制造覆盖幻觉。

## 刷题反馈回流

刷题不是终点。题库只负责发现不会，学习项目要负责修复不会。

回流路径：

```text
错题或薄弱 atom
→ 章节学习档案或课程层知识修复
→ 必要时生成方法卡片或 Zettelkasten 候选
→ MOC 或项目 dashboard 更新学习地图
```

推荐分层：

- 项目/课程层：保存错题、薄弱点、章节修复和本次教材语境；
- Zettelkasten：只接收能跨章节、跨项目复用的稳定概念或方法；
- MOC/dashboard：组织章节、题库、修复卡和永久卡片之间的导航。

## 与 guided learning 的关系

`guided-learning-session-governance.md` 负责单次学习会话如何讲、如何提问、如何记录。

本 reference 负责当用户选择“刷题学习法”时，如何把原文材料变成可检测的 atom 和题库。

两者推荐配合：

```text
章节 TODO 控制主线
→ atom 覆盖表保证知识点不漏
→ 题库检测暴露薄弱点
→ guided learning 对薄弱点做微型补课
```

## 反哺边界

可以进入通用 Skill 的内容：

- 逐段读取与段落功能分类；
- atom 抽取标准；
- 覆盖表字段；
- 题库化与反馈回流协议。

必须留在具体项目或 TASK 的内容：

- 某本教材的具体 atom 列表；
- 具体题库 JSON；
- 用户错题记录；
- 具体章节页码、段落编号和学习盲区。

## 迁移状态

当前规则来自本地 SMK 教材学习项目和本地刷题系统方法论对照，状态为：

```text
structural-green / forward-test-pending
```

含义：

- 已适合作为 course-driven 学习项目的结构化分支；
- 尚未在多个新教材项目中验证；
- 后续应在另一门非实证资产定价课程中 forward-test。
