# 评测与迁移

## 四层评测

1. **案例复现**：当前案例达到预设 Green。
2. **教师对照**：能解释路线相同点、差异和适用条件。
3. **Skill 回归**：变更未破坏既有案例和模板。
4. **迁移评测**：在未参与提炼的新案例上成功路由并取得证据。

## 迁移状态

- `not-tested`：只有来源案例。
- `partial`：新案例部分成功，边界仍在收窄。
- `validated`：至少一个新案例通过预设评测，且没有依赖来源案例固定值。

## Forward-test 纪律

- 使用新案例的原始输入，不提供来源案例答案。
- 只给测试者 Skill 和必要任务上下文。
- 预先写 Green，避免看到结果后改标准。
- 记录首个失败层，不让测试者从预期答案反推。

## 变更升级门槛

可以升级已有 Skill：

- 同一规则在至少一个真实案例中产生明确价值；
- 规则有清楚的触发条件与停止条件；
- 不依赖个案固定值；
- 能增加回归测试或 evaluation。

适合创建新 Skill：

- 职责可独立描述；
- 输入输出稳定；
- 与已有 Skill 的所有权边界清晰；
- 至少有一个完成案例和一个可设计的迁移案例。

否则先保留为 TASK 发现或现有 Skill 的 reference。
