# Guided Learning Session Governance

## 定位

本 reference 用于把课程、教材、考试备考或长期学习项目中的单次对话，治理成可追踪、可复习、可反哺 Skill 的学习会话。

它不替代 `simon-learning-card-builder`。Simon 负责知识卡片和首次学习结构；本 reference 负责一次学习会话如何互动、如何留痕、如何更新全局进度。

如果任务是把整本教材组织成长期项目，而不只是治理某次学习会话，先读取 `textbook-learning-project-workflow.md`。本 reference 只处理其中的“会话层”。

## 适用场景

- 用户正在学习一本书、课程、考试材料或技术教程；
- 学习周期跨多次对话；
- 用户希望保留问题、讲解、理解检测、知识盲区和后续计划；
- 内容含高风险或易过期规则，需要外部核验；
- 学习结果后续可能反哺 Skill、workflow、TASK 模板或知识卡片。

## 会话治理主线

每次学习会话按以下结构推进：

```text
回看近期上下文
→ 确认本次学习单元与主线 TODO
→ 探索学习者已有理解
→ 聚焦讲解一个小块
→ 理解检测或最小复述
→ 记录掌握点和盲区
→ 更新全局进度或章节档案
```

## 学习单元 TODO 控制

当学习对象是书籍章节、课程课时或一组连续知识点时，正式讲解前应先建立学习单元 TODO。它的作用不是限制用户提问，而是防止对话被临时问题带散。

TODO 至少包含：

| 字段 | 含义 |
|---|---|
| 序号 | 学习顺序 |
| 知识点 | 本单元必须覆盖的概念、方法或接口 |
| 角色 | `核心主线 / 迁移接口 / 第二轮 / 停车场` |
| 状态 | `todo / learning / done / defer / parking` |
| 通过标准 | 学习者能用自己的话完成的最小复述或练习 |

推荐状态语义：

```text
todo      尚未讲
learning  已开始讲，但还没完成最小复述
done      已讲完，并通过最小复述或练习
defer     第一轮主动延后
parking   发散问题，暂不进入本单元主线
```

章节或课时 Green：

```text
核心主线 TODO 全部 done
→ 迁移接口已说明或明确 defer
→ 停车场问题有后续处理位置
→ 完成最小复述
```

核心 TODO 未完成时，不应进入下一章或下一课时；若用户想跳转，应先显式记录跳转原因和未完成项。

## 刷题学习模式

当用户希望把教材或课程切换为“刷题学习法”时，不应直接按章节粗略生成少量题。先读取 `atomized-reading-to-quiz-workflow.md`，把学习单元拆成原子知识点覆盖表，再由覆盖表生成题库。

推荐衔接关系：

```text
学习单元 TODO
→ 逐段读取材料
→ 段落功能分类
→ 原子知识点覆盖表
→ 低摩擦题目
→ 错题与薄弱 atom 回流学习档案
```

此时章节 TODO 负责“主线不跑偏”，atom 覆盖表负责“知识点不漏”，题库负责“暴露不会”。

若项目尚未建立章节边界、学习档案和回流位置，应先读取 `textbook-learning-project-workflow.md` 建立项目承载，再进入题库化。

## 引导式讲解协议

当用户提出学习问题时，默认不急于长篇讲解，先判断问题属于哪类：

| 类型 | 处理方式 |
|---|---|
| 主线内问题 | 直接挂到当前学习单元 TODO，推进讲解 |
| 主线旁路问题 | 简短解释，再拉回当前主线 |
| 发散问题 | 放入停车场，记录后续处理位置 |
| 高风险事实问题 | 先核验，再讲解 |

推荐教学节奏：

1. 问学习者已有理解，而不是假设零基础。
2. 在已有理解上补足概念、机制、例子或反例。
3. 一次只讲一个可消化组块。
4. 用最小复述、场景题或对比题检测理解。
5. 若理解不稳，换类比、换例子或降一级解释。

当教学内容包含模型、统计、计量、工程机制或抽象方法时，优先采用“直觉到形式化”的讲解结构：

```text
直觉问题
→ 最小公式、伪代码或结构图
→ 每个参数/步骤的含义
→ 结果变化的可能解释
→ 回到用户项目语境
→ 标注后续章节或 TASK 回收位置
```

这类结构适合把主线旁路问题讲清楚，同时避免把当前章节拖入完整后续章节。

每轮讲解开始时，最好显式声明正在推进哪个 TODO，例如：

```text
这一轮推进 Ch.1 TODO 1-2：样本口径与非平衡 panel。
```

每轮结束时，更新 TODO 状态；不要等整章结束才一次性补状态。

## 会话记录模板

每次学习会话至少记录：

```markdown
## YYYY-MM-DD 学习会话

### 本次单元

### 本轮推进的 TODO

### 用户原始问题

### 用户初始理解

### 本次讲解

### 理解检测

### 用户复述或回答

### 已掌握

### 知识盲区

### 需要回看或停车场

### TODO 状态更新

### 下一步
```

如果项目已有逐章档案或 TASK log，应优先追加到现有文件，不要为同一进度创建多个互相竞争的 tracker。

## 全局进度治理

长期学习项目应有一个全局入口，承担 single source of truth：

- 当前学习单元；
- 已完成单元；
- 进行中单元；
- 核心 TODO 状态；
- 已掌握概念；
- 未解决盲区；
- 下一步学习计划；
- 需要反哺的 Skill / workflow 候选。

单次会话记录保存“发生了什么”；全局入口保存“现在学到哪里”。两者不要混用。

## 高风险事实核验

当学习内容包含会随时间变化、会影响考试/法律/财务/医疗/生产环境决策的事实时，不能只凭记忆作答。

需要核验的典型内容：

- 最新政策、法规、考试规则、税率、金额门槛；
- 软件/API/工具版本行为；
- 金融、法律、医疗等高风险建议；
- 练习题标准答案或计算公式；
- 用户明确要求“最新”“现在”“查一下”的内容。

核验后应记录：

```text
来源
检索日期
结论
不确定性
是否影响本项目规则
```

若资料冲突，应明确告诉用户冲突点，不把不确定结论写成 Skill 规则。

## 反哺边界

可以提升到 Skill / workflow 的内容：

- 稳定的学习会话结构；
- 进度追踪和会话记录模板；
- 高风险事实核验规则；
- 学习单元 TODO、主线旁路与停车场机制；
- 能被多个学习项目复用的理解检测方式。
- 从长篇材料逐段抽 atom、建立覆盖表并接入刷题反馈回流的结构规则。

必须留在具体项目或 TASK 的内容：

- 具体考试大纲、分值、题库、教材页码；
- 用户个人进度、知识盲区、备考日期；
- 某次学习会话的原始问答；
- 尚未在其他学习项目中验证的提示词表达。
- 具体教材章节的 atom 列表、题库 JSON、错题记录和项目固定样例。

## 迁移状态

当前规则来自外部提示词样本和本地学习项目实践的结构对照，状态为：

```text
structural-green / forward-test-pending
```

含义：

- 已可作为结构规则调用；
- 尚未声称在多个新学习项目中验证；
- 后续应在至少一个非 CFP、非本项目教材学习场景中 forward-test。
