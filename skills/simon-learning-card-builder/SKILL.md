# Simon Learning Card Builder

把按来源顺序组织的学习资料，转换成“首次学习指南 → 原始材料 → 永久知识卡片与知识地图”的三层学习系统。

## 核心原则

1. 把 `Day`、章节、视频课时和论文主题统一称为“学习单元”。
2. 先设计学习者怎样形成认知组块，再决定怎样拆卡。
3. 永久卡片只保存可独立理解、迁移和验证的知识。
4. 代码是可选证据，不是必需输入。
5. 卡片数量由独立问题决定，不按章节数或既有案例套用。
6. 结论强度不得超过证据强度。
7. 优先复用或更新已有卡片，避免同义重复。

## 工作流

### 1. 清点材料

读取用户指定目录及其 README、Markdown、代码、PDF/电子书导出、转录文本和已有卡片库。

优先使用 `rg --files`、`rg '^#{1,6} '` 和文件清单获取：

- 学习单元边界；
- 原始标题与可链接锚点；
- 示例、图表、代码和实验结果；
- 已有 README、指南、地图与永久卡片。

根据材料类型读取 [references/material-types.md](references/material-types.md)。

### 2. 建立知识基线

检索已有永久卡片，将内容分为：

- `新增`：知识库中尚不存在，且有迁移价值；
- `深化`：已有知识获得新的边界、失败模式或证据；
- `复用`：结构不变，只更换案例、输入或参数；
- `材料细节`：版本地址、固定值、书中叙事或单篇论文局部结果。

新增内容创建卡片；深化内容优先更新旧卡；复用内容只在指南和地图中链接；材料细节留在原始材料或指南。

### 3. 设计学习组块

围绕完整问题组织组块，不按原目录机械切分：

```text
问题情境
→ 原理或静态分析
→ 示例/动态观察/论证
→ 练习或本地验证
→ 掌握检查
```

首次学习指南必须说明：

- 开始前应具备什么；
- 第一轮必须学什么；
- 第二轮可以延后什么；
- 原始材料和卡片的阅读顺序；
- 小练习、通过标准和最小复述。

### 4. 决定是否制卡

仅在以下条件大多成立时创建永久卡片：

- 能回答一个独立问题；
- 脱离当前案例仍能理解；
- 有自己的适用条件或失败模式；
- 能在其他学习或实战任务中复用；
- 合并会掩盖重要上下位关系。

不要为每个 API、书中每个小节或每篇论文机械建卡。

### 5. 建立三层产物

默认创建或更新：

```text
卡片笔记/
├── README.md
├── 00-首次学习/
├── 10-知识地图/
└── 20-永久知识卡片/
```

永久卡片内部按“领域 → 抽象层级”组织：

```text
00-基础概念
10-通用方法 / 实战方法 / 组合模式
20-专项技术 / 实现细节
```

使用 [references/templates.md](references/templates.md) 中的模板。保持现有知识库的目录、Frontmatter 和命名习惯。

### 6. 链接证据

优先建立可直达证据的链接：

- Markdown：`[[完整案例路径/笔记#具体标题]]`
- 视频转录：标题锚点加时间戳
- 书籍：章节、小节、页码或稳定块引用
- 论文：论文笔记标题、页码、表格、命题或结果段
- 代码：链接整个脚本，并说明它验证什么

不同案例存在同名文件时，必须使用完整库内路径。

证据分级：

```text
L1-static              静态线索或文本主张
L2-runtime             运行时观察或直接材料证据
L3-local-reproduction  本地复现、推导或交叉比较
L4-end-to-end          端到端任务验证
```

`evidence_level` 表示结论证明程度，`status` 表示学习者掌握程度，不要混用。

### 7. 更新入口

更新：

- 案例或材料目录 README；
- 卡片库 README；
- 首次学习指南；
- 增量知识地图；
- 被深化的旧卡及其相关链接。

同一知识库存在多个相同 Day 时，指南和地图使用案例名前缀，例如：

```text
唯品会Day19首次学习指南.md
唯品会Day19增量知识地图.md
```

永久卡片通常不使用案例名或 Day 命名。

### 8. 校验

运行：

```bash
node scripts/validate_obsidian_links.js \
  --vault "/absolute/path/to/vault" \
  --scope "/absolute/path/to/created-or-updated-area"
```

修复全部：

- 缺失文件；
- 失效标题锚点；
- 同名目标歧义。

同时人工检查：

- 新增与复用是否分开；
- `parent` 是否真是上下位关系；
- 固定业务值是否被误写成通用知识；
- 推测是否被误写成已确认结论；
- README、指南、地图和卡片能否互相到达。

## 材料类型路由

- 技术课程或视频：强调问题链、代码/运行时证据和可复现实验。
- 书籍章节：强调概念递进、例题、图表和章节论证；不要求代码。
- 多篇论文主题集：先构建概念、机制、证据与分歧矩阵，再制作主题综合卡；不要把逐篇摘要当永久卡片。
- 混合材料：以用户的学习目标为主线，不以文件格式为主线。

详细规则见 [references/material-types.md](references/material-types.md)。

## 输出纪律

- 保留原始笔记，不用永久卡片替代原材料。
- 不复制大段受版权保护的书籍或论文正文，只记录短证据定位和自己的概括。
- 不创建空目录、占位卡片或无实际链接的“未来支持”文件。
- 用户要求实际整理时，完成文件创建、入口更新和链接校验，不只给方案。
- 用户只要求判断或总结困惑时，不擅自创建 Skill 或重组资料。
