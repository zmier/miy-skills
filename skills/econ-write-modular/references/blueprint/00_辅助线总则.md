# 辅助线总则

辅助线是论文写作中的中间工件：它们不一定进入最终正文，但用于持续管理一篇论文自己的核心发现、概念术语、结构大纲、逐段细纲、论断证据、结果叙事和审稿风险。

## 适用场景

当用户要求写整篇论文、重写引言、做全文检查、大修、统一术语、搭框架、整理逻辑、生成逐段提纲、检查图表叙事或准备返修时，先使用辅助线。

如果用户只是要求局部润色，也应快速判断该段是否可能受核心发现、术语表或逐段细纲约束。若存在主线漂移、术语混用或无证据强论断，先指出结构性问题，再做语言改写。

## 两类文件

Skill 参考文件位于：

```text
econ-write-modular/references/blueprint/*.md
```

它们说明每种辅助线怎么建、怎么用、何时更新。

用户论文状态文件通常位于用户项目中：

```text
writing-state/*.md
```

它们保存某篇论文自己的核心发现、术语、结构和证据。处理用户论文时，不要把 skill 内部参考文件当作用户论文状态文件。

## 推荐的 writing-state 结构

```text
writing-state/
  00_项目管理.md
  00_一句话核心发现.md
  01_研究问题与贡献地图.md
  02_概念术语表.md
  03_变量概念映射表.md
  04_机制链条.md
  05_三级目录大纲.md
  06_逐段TopicSentence细纲.md
  07_论断证据表.md
  08_结果叙事表.md
  09_审稿人风险清单.md
  10_更新日志.md
  log.md
```

最低限度应先建立：

```text
00_一句话核心发现.md
02_概念术语表.md
05_三级目录大纲.md
06_逐段TopicSentence细纲.md
07_论断证据表.md
```

## Obsidian 链接规则

如果用户项目是 Obsidian 知识库，辅助线中涉及其他文件时，优先使用 Obsidian 双链写法，例如：

```markdown
[[00_一句话核心发现]]
[[02_概念术语表]]
[[04_机制链条]]
```

不要用反引号包裹文件名来表达文件引用。反引号只用于代码、命令、字段名或非链接的字面量。

若需要引用不在同一目录的文档，可使用带别名的双链：

```markdown
[[相对路径/文件名|显示名称]]
```

## 项目管理与讨论台账

建议在 `writing-state/` 中区分两个总控文件：

- [[00_项目管理]]：任务看板，记录哪些辅助线已完成、哪些正在讨论、下一步做什么。
- [[log]]：讨论台账，记录为什么这样判断、依据是什么、影响哪些文件、还有哪些待追踪问题。

不要把二者合并。项目管理文件追踪“做到了哪里”；讨论台账追踪“为什么这样做”。二者可以互相双链。

## 工作流

1. 写正文前：检查是否已有 `writing-state/`。若没有，建议或创建最小辅助线。
2. 写正文中：按任务读取对应辅助线，使正文服从核心发现、术语、结构和证据。
3. 写正文后：检查是否引入新概念、新论断、新结果解释或新风险，并反向更新辅助线。

概念治理补充规则：当概念既有写作权重又有机制从属关系时，[[02_概念术语表]] 应使用双坐标：A/B/C/D 表示写作权重，M 编号表示机制路径位置。后续 [[03_变量概念映射表]]、[[04_机制链条]] 和 [[06_逐段TopicSentence细纲]] 应继承同一 M 编号。

## 任务与辅助线

| 写作任务         | 必读辅助线                       |
| ------------ | --------------------------- |
| 摘要           | 一句话核心发现、论断证据表、结果叙事表         |
| 引言           | 一句话核心发现、研究问题与贡献地图、机制链条、逐段细纲 |
| 文献综述         | 研究问题与贡献地图、概念术语表             |
| 理论机制         | 机制链条、概念术语表、变量概念映射表          |
| 数据变量         | 变量概念映射表、概念术语表               |
| 实证结果         | 结果叙事表、论断证据表、变量概念映射表         |
| 稳健性、异质性、机制检验 | 结果叙事表、机制链条、审稿人风险清单          |
| 结论           | 一句话核心发现、结果叙事表、审稿人风险清单       |
| 全文审读         | 全部辅助线                       |

## 输出优先级

全文检查或大修时，问题排序应优先于语言润色：

1. 核心发现是否漂移；
2. 概念术语是否漂移；
3. 论断是否缺证据；
4. 机制链条是否闭合；
5. 结构顺序是否合理；
6. 图表是否服务一句话结论；
7. 局部语言是否需要润色。

辅助线本身也可以被修改。如果正文和辅助线冲突，先判断是正文跑偏，还是辅助线需要更新；不要机械服从旧辅助线。
