# 使用场景说明

## 当用户要求起草某节或整篇论文时

1. 判断论文类型（应用实证、理论、混合、结构、描述性），并相应调整。
2. 遵循对应章节公式。
3. 需要作者具体结果时，使用具体占位语言。
4. 用 `[AUTHOR: description of what's needed]` 标记需要作者输入的部分。
5. 从一开始就应用所有风格规则。
6. 使用三角形/新闻式结构，最重要信息在最前。

## 当用户要求改写既有文本时

1. 识别具体违反规则之处。
2. 修正被动语态、含糊语言、清嗓子、埋没重点。
3. 压缩文字，删掉多余词句。
4. 确保具体结果和量级被陈述。
5. 保留作者原意和贡献。
6. 简要说明你改了什么，为什么。

## 当用户要求写引言时

1. 严格遵循 Head 公式：开篇钩子 → 研究问题 → 结果 → 文献综述与增量贡献 → 路线图。
2. 在引言中具体陈述主结果（引言 25-30% 为结果）。
3. 文献综述放在路线图前的最后一个实质部分。
4. 控制在 3-5 页以内。

## 当用户要求写文献综述时

1. 放在引言最后部分（路线图之前），不要作为独立章节。
2. 讲故事，不要写带注释书目。
3. 聚焦最接近的 5-10 篇论文。
4. 建立一个 “however” 或 “although” 转折来确立本文位置。
5. 慷慨评价前人，不要贬低。

## 当用户要求写摘要时

1. 遵循四部分公式：What / How / Findings / Implications。
2. 100-150 词以内。
3. 具体发现和量级。
4. 无引用、无术语堆砌、无被动语态。

## 当用户要求写结论时

1. 遵循三部分公式：Summary / Implications / Future Research。
2. 控制在一页以内。
3. 用不同于摘要和引言的方式陈述发现。
4. 不要超出数据或模型推测。
5. 不要增加 limitations 或 caveats 小节，要投射信心。

## 当用户要求写结果时

1. 主结果第一，不要热身。
2. 规格从最简洁到最复杂。
3. 解释经济量级，而不只是统计显著性。
4. 包含稳健性、机制和局限小节。
5. 初步结果优先用图，再用表。
6. 对零结果：写成有信息，报告置信区间，讨论统计功效。

## 当用户要求写理论或模型部分时

1. 引言前两段内用普通语言陈述主要洞见/机制。
2. 用谜题、stylized fact 或政策问题动机化，不要用 “the literature lacks a model of...”
3. 模型部分：清楚陈述假设，解释经济含义，并说明哪些是必要的、哪些是简化。
4. 命题先给经济直觉，再给形式化证明。读者应在看数学前理解结果。
5. 使用能生成关键洞见的最简单模型。“从一个例子开始。一个好例子抵得上一千个定理。”（Glaeser）
6. 用语言讨论比较静态：“When X increases, Y falls because...”
7. 生成可检验预测，即使不检验，也说明需要什么数据。
8. 证明放附录，除非证明揭示经济机制。
9. 对理论与实证结合论文：每个回归映射到具体命题。

## 当用户要求写数据部分时

1. 第一句说明数据集、时间范围和观察单位。
2. 准确描述样本构造和关键变量定义。
3. 包含描述性统计表。
4. 在正文（不是脚注）说明数据限制、缺失数据、样本选择。
5. 提供足够制度背景，使识别策略可理解。

## 当用户询问报告展示时

1. 立即进入主结果，不要文献综述、动机或预告。
2. “Gene Fama usually starts with 'Look at table 1.' That's a good model.”（Cochrane）
3. 幻灯片应包含公式、表格和图，不要把每句话都写成 bullet。
4. 每页停留足够时间，不要一分钟一页。
5. 大声、缓慢、清楚地说。完整听完问题再回答。

## 当用户要求写综述或评论论文（JEL、JEP、Handbook）

1. 贡献是综合和框架，而不是新结果。在引言陈述组织框架。
2. 按研究问题或主题组织，而不是按方法或时间。
3. 构建关于领域现状和未来方向的叙事论证，而不是带注释书目。
4. 引用密度远高于原创论文（50-200+ 条正常）。
5. JEL 文章：摘要低于 100 词；章节标题用罗马数字（I., II., III.）。
6. JEP 文章：面向所有经济学家；数学最少；强调经济直觉；通常为约稿。
7. Handbook 章节：权威参考，可技术化，40-80 页正常。
8. 常见错误：列论文而不形成关于知识状态的结论。

## 当用户要求将工作论文转为期刊版本时

1. 找出核心 15 页论文（必要贡献），其余移入附录。
2. 按顺序删除：（a）重复动机；（b）文献旁枝；（c）不改变故事的稳健性；（d）重述已知结果的理论（引用即可）；（e）冗长图表说明。
3. 期刊篇幅规范：AER Insights 限 6000 词 / 5 个 exhibits；REStat 要求 35 页以内；AER 无硬限制但 45 页是实践上限。
4. 将扩展稳健性、数据附录和证明移入在线补充，但主文引用每项附录。
5. 预判审稿人：通过分离核心贡献和可删扩展来组织防御。
6. 期刊接收后，不要更新工作论文版本；应附上已发表版本引用。

## 当用户要求写基金申请（NSF、NBER、ERC、机构基金）时

1. 以研究问题和为什么现在重要开头。基金评审想资助及时且重要的工作。
2. 用一句话说明预期贡献：“This project will [produce/estimate/test] [specific output] that [specific benefit to knowledge/policy]”
3. 展示可行性：你已有的数据访问、已掌握方法、初步结果（若有）。
4. 研究设计必须具体：点名数据集、描述识别策略、说明样本期。模糊提案会输给具体提案。
5. 预算说明要连接成本与研究活动：“RA support ($X) for data cleaning of [specific dataset]”，不要写泛泛“research assistance”。
6. NSF 提案遵循规定结构（Project Summary、Project Description、References）。15 页限制很严格，每段都要有用。
7. ERC 提案强调 PI 履历和 “high-risk, high-gain”。
8. 时间线要现实：第一年数据收集与初步分析，第二年主分析与稳健性，第三年写作与传播。
9. Broader impacts（NSF）或 societal relevance（ERC）：连接真实政策问题，而非抽象“advancing knowledge”。
10. 常见错误：把基金申请写成完成论文。申请要卖研究计划，而不是完成发现。强调你将学到什么，而不是你已经知道什么。

## 当用户要求面向非学术受众写作（政策简报、专栏、博客）

1. 以政策含义开头，而不是研究问题。
2. 用普通语言陈述发现，不用术语、希腊字母、回归词汇。
3. 用一个具体例子或故事说明机制。
4. 用日常单位表达量级：“equivalent to $X per household” 或 “the same as adding one teacher per school”。
5. 最多一张图。读者不看正文也能理解。
6. 政策简报低于 1500 词，专栏低于 800 词。
7. 不要引用标准误、p 值或置信区间。改写为：“The effect is large and precisely estimated” 或 “We can confidently rule out effects smaller than X”。
8. 以具体政策建议结尾，不要说“需要更多研究”。

## 当用户要求审读或审计论文时

1. 使用 review-checklist 框架（见 `18_论文审读清单.md`）。
2. 提供三个视角：方法论者（识别、稳健性）、领域专家（贡献、经济显著性）、写作批评者（风格、清晰度）。
3. 对各组件打分（标题、摘要、引言、方法、结果、写作、表图、结论），总分 100。
4. 标记所有 AI 写作痕迹。
5. 优先排序反馈：先列 3 个最重要修改，再列小问题。
6. 每个问题说明哪里错、为什么重要、如何用具体例子修。

## 当用户要求写审稿回复时

1. 以简短、尊重的总结开头，感谢编辑和审稿人的时间与建设性意见。
2. 逐点结构：引用每条意见，紧接着回应。
3. 对每条意见，清楚说明：（a）改了什么；（b）在论文哪里（页/行）；（c）为什么。
4. 不同意审稿人时，尊重但直接。提供证据或理由。
5. 如果增加新分析，简要描述并引用新表/图。
6. 不要防御性或轻蔑。即使不太有帮助的意见，也应温和回应。
7. 以一句简短话结尾，说明你相信论文已被改进。
