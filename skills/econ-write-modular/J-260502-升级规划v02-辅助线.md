# J-260502：econ-write-modular 升级规划 v02：辅助线与中间工件层

## 一句话目标

在 `econ-write-modular` 中新增“辅助线 / 中间工件层”，让 skill 不只会写各章节正文，还能先建立并持续维护论文的核心发现、概念术语、结构大纲、逐段细纲、论断证据表等写作状态文件。

## 为什么需要 v02

上一份规划 `J-260502-升级规划.md` 主要解决的是：

> 如何用已发表中文经济学论文 PDF，补充中文语境经验和 examples。

这份 v02 解决的是另一个更底层的问题：

> 论文写作不是直接生成正文，而是先搭建一组“辅助线”。这些辅助线不一定进入最终论文，但会控制全文主线、术语、结构、证据和贡献不漂移。

换句话说，上一份规划关注“范例驱动”，这份规划关注“写作状态管理”。

## 本规划的现实来源：一篇大修草稿与导师语音建议

这份 v02 规划不是从抽象方法论里凭空设计出来的，而是来自一篇正在“大修”的经济学草稿及其导师指导过程。

当前案例包括两个关键文档：

- 草稿入口：`/Users/narra/Documents/alib/Writer/03 Projects/J-260128-重大结项/Docs/小论文部分/草稿.md`
- 导师语音转写：`/Users/narra/Documents/alib/Writer/03 Projects/J-260128-重大结项/Docs/小论文部分/10-第一轮返修J-260415/秋懿老师260416_ABM文章-修改建议-原文.md`

其中，`草稿.md` 本身更像一个总入口，链接到引言、理论机制、模型构建、结果讨论和结论等章节；真正触发“辅助线”思考的，是导师在语音转写中对这篇 ABM / 计算金融实验文章提出的连续写作诊断。

导师建议中反复出现的核心问题，并不是某一句话是否顺，而是全文是否有一套可持续控制的中间结构：

- 文章一开始就要能用一两句话说清楚“研究什么、发现什么”；
- 全文最后真正让读者记住的，往往就是这一两句话，其他内容都必须服务于它；
- 如果使用“错配”等核心概念，必须先界定什么叫错配，并检查文献中是否已有稳定用法；
- 每一段都要能概括出它的核心作用，由此形成文章的骨架；
- 高概念和技术性用语不能不断新增，标题和正文都要压缩概念密度；
- 风险传导、风险再分配、去杠杆、顺周期、资本约束等术语必须统一，否则读者会失去主线；
- 图表不能只是展示计算结果，而应当各自服务一个明确结论，能用一句话说出“从表中可知什么”；
- 不重要的图表应进入附录，正文只保留支撑主线的证据；
- 需要精读目标期刊的相近论文，概括其每一段的功能，再把这种段落功能转换为自己文章的写法。

因此，这里所谓“辅助线”，本质上是把导师口头指导中隐含的写作判断，转化为可保存、可更新、可被 Codex 调用的中间文件。它不是额外增加写作负担，而是把大修时最容易丢失的判断显性化。

对应到本 skill 的设计，这个案例至少说明需要新增以下写作状态文件：

- `00_一句话核心发现.md`：承接“研究什么、发现什么”，控制全文主线。
- `03_概念术语表.md`：承接“错配”等核心概念界定，控制术语边界。
- `06_三级目录大纲.md`：承接“标题概念不能过密”，控制章节层级。
- `07_逐段TopicSentence细纲.md`：承接“每一段的核心作用”，控制段落骨架。
- `08_论断证据表.md`：承接“每个结论有没有证据支撑”，控制论断与材料的对应关系。
- `09_结果叙事表.md`：承接“每个图表表达一句话”，控制结果部分的叙事顺序。
- `10_审稿人风险清单.md`：承接“读者会不会看不懂、觉得不专业、认为概念太散”，控制潜在审稿风险。

从这个意义上说，v02 的重点不是让 skill 多一批模板，而是让 skill 学会陪作者维护一套“论文施工辅助线”：先把主线、术语、骨架和证据摆正，再进入正文改写。

## 当前两个 Skill 的共同盲点

### 1. `econ-write-modular` 的盲点

`econ-write-modular` 已经有丰富的经济学写作原则，但主要回答：

- 摘要应该怎么写；
- 引言应该怎么写；
- 模型、数据、结果、结论应该怎么写；
- 表格、图形、审读清单应该怎么处理。

它还没有系统要求作者在写正文前建立：

- 一句话核心发现；
- 核心研究问题；
- 概念/术语表；
- 变量-概念映射表；
- 机制链条；
- 三级目录大纲；
- 逐段 topic sentence 细纲；
- 论断-证据表；
- 结果叙事表；
- 审稿人风险清单。

所以 Codex 可能能把某一段改得更顺，但全文主线、术语和证据仍可能漂移。

### 2. `research-paper-writing-zh` 的盲点

`research-paper-writing-zh` 结构更成熟，已经有：

- paper story；
- claim-evidence alignment；
- reverse outlining；
- adversarial review；
- section-level references 和 examples。

但它仍然没有把这些内容显式产品化为一组可维护的“中间文件”。它会要求做反向提纲和证据对齐，却没有规定这些工件应保存在哪里、如何命名、何时更新、如何被后续章节调用。

因此，两个 skill 都还停留在“章节写作 skill”，尚未升级为“论文建造 skill”。

## 核心判断

高质量论文写作至少有三层：

```text
原则层：知道什么是好写作
范例层：知道真实论文怎么写
辅助线层：持续管理本文自己的主线、术语、证据和结构
```

目前：

- `econ-write-modular` 已有较强的原则层；
- v01 规划准备补充范例层；
- v02 规划要补上辅助线层。

真正好用的经济学写作 skill，应该要求正文写作始终围绕这些辅助线展开。

## 辅助线的定义

“辅助线”是指论文写作过程中用于控制全文一致性的中间工件。

它们有三个特点：

1. **不一定进入最终正文**：像画图的辅助线，最终可以隐藏。
2. **必须在写作过程中持续存在**：每次改引言、结果、摘要都要回看。
3. **会反向约束正文**：正文不能偏离核心发现、术语表、证据表和结构大纲。

辅助线不是普通笔记，而是写作状态文件。

## Skill 内部参考文件与项目状态文件的区别

需要区分两类文件：

### 1. Skill 参考文件

位置：

```text
econ-write-modular/references/blueprint/*.md
```

作用：

- 告诉 Codex 什么是辅助线；
- 每种辅助线怎么写；
- 什么时候更新；
- 如何用它约束正文。

这些文件是 skill 的“方法论”。

### 2. 用户论文状态文件

位置由用户项目决定，例如：

```text
某篇论文项目/writing-state/*.md
```

作用：

- 保存某篇论文自己的核心发现、术语、结构和证据；
- 供后续写摘要、引言、结果、结论时反复调用；
- 随论文修改持续更新。

这些文件是论文的“施工辅助线”。

## 辅助线文件设计

### 00_一句话核心发现.md

作用：控制整篇论文的中心。

它回答：

```text
本文最重要的发现是什么？
这个发现包含哪几个必要元素？
是否能用一句话讲清楚 X、Y、机制和贡献？
```

建议模板：

```markdown
# 一句话核心发现

## 当前版本

[X] 通过 [机制 M] 影响 [Y]，并在 [场景/样本/冲击] 中表现为 [方向/量级/分布变化]。

## 必须包含的元素

- 核心解释变量 X：
- 核心结果变量 Y：
- 关键机制 M：
- 识别来源或研究场景：
- 最重要结果：
- 贡献边界：

## 不能偏离的表述

- 不要把本文写成：
- 不要声称：
- 不要混用：

## 更新记录

- YYYY-MM-DD：初版。
```

使用规则：

- 写摘要前必须读取。
- 改引言前必须读取。
- 结果和结论若出现新重点，必须反向更新。

### 02_概念术语表.md

作用：防止概念漂移和术语混用。

建议模板：

```markdown
# 概念术语表

| 概念 | 主术语 | 可接受替代表述 | 禁用/慎用表述 | 定义 | 首次出现位置 |
|---|---|---|---|---|---|
| 资本约束 | 资本约束 | 银行资本约束 | 融资约束、资金约束 |  |  |
| 尾部风险 | 尾部风险 | 下行尾部风险 | 系统性风险、风险扩散 |  |  |

## 术语使用规则

1. 后文统一使用“主术语”。
2. 替代表述只在解释时出现。
3. 禁用表述除非重新定义，否则不使用。
```

使用规则：

- 所有改写任务都应读取。
- 全文检查时必须用它搜索术语漂移。
- 如果引入新概念，必须先更新此表。

### 07_论断证据表.md

作用：保证每个核心论断都有证据。

建议模板：

```markdown
# 论断证据表

| 论断 | 所在章节 | 证据类型 | 对应表图/文献/模型 | 支撑状态 | 风险 |
|---|---|---|---|---|---|
|  | 引言 | 表格结果 | 表 3 | 已支撑 |  |
|  | 结果 | 稳健性 | 表 5 | 需补强 |  |

## 支撑状态

- 已支撑
- 需补证据
- 需弱化

```

使用规则：

- 写摘要和引言时尤其重要。
- 任何强论断都必须进入此表。
- 没有证据的论断必须弱化或删除。

### 08_结果叙事表.md

作用：把一组实证表格转化为论文叙事。

建议模板：

```markdown
# 结果叙事表

| 结果模块 | 表图 | 要回答的问题 | 核心发现 | 经济含义 | 支撑哪个主结论 |
|---|---|---|---|---|---|
| 基准结果 | 表 1 | X 是否影响 Y |  |  |  |
| 稳健性 | 表 2 | 结果是否依赖测度/样本/模型 |  |  |  |
| 异质性 | 表 3 | 效应在哪些主体更强 |  |  |  |
| 机制检验 | 表 4 | M 是否是传导渠道 |  |  |  |

## 结果写作顺序

1. 先写最重要结果。
2. 再写量级和经济含义。
3. 再写稳健性。
4. 最后写机制或边界条件。
```

使用规则：

- 写结果部分前必须建立。
- 如果表格变化，应更新叙事表。
- 如果叙事表中某个结果不支撑主结论，应移到附录或弱化。

### 2. 写正文中：正文必须引用辅助线

不同任务应读取不同辅助线：

| 写作任务 | 必读辅助线 |
|---|---|
| 摘要 | 一句话核心发现、论断证据表、结果叙事表 |
| 引言 | 一句话核心发现、研究问题与贡献地图、机制链条、逐段细纲 |
| 文献综述 | 研究问题与贡献地图、概念术语表 |
| 理论机制 | 机制链条、概念术语表、变量概念映射表 |
| 数据变量 | 变量概念映射表、概念术语表 |
| 实证结果 | 结果叙事表、论断证据表、变量概念映射表 |
| 稳健性/异质性/机制检验 | 结果叙事表、机制链条、审稿人风险清单 |
| 结论 | 一句话核心发现、结果叙事表、审稿人风险清单 |
| 全文审读 | 全部辅助线 |

### 3. 写正文后：反向更新辅助线

每次完成重要正文修改后，Codex 应检查：

1. 是否引入新概念？如果有，更新概念术语表。
2. 是否改变核心发现？如果有，更新一句话核心发现。
3. 是否新增强论断？如果有，更新论断证据表。
4. 是否改变结果解释？如果有，更新结果叙事表。
5. 是否暴露新风险？如果有，更新审稿人风险清单。

### 场景 1：用户要求“帮我写引言”

   - `04_机制链条.md`
   - `06_逐段TopicSentence细纲.md`
5. 再写引言正文。
6. 写完后更新 `07_论断证据表.md`。

### 场景 2：用户要求“帮我改这段”

推荐流程：

1. 判断段落属于哪个章节。
2. 读取对应章节指南。
3. 读取：
   - `00_一句话核心发现.md`
   - `02_概念术语表.md`
   - 对应章节的逐段细纲。
4. 判断该段是否服务于既定 topic sentence。
5. 改写段落。
6. 如术语或论断变化，更新辅助线。

### 场景 3：用户要求“帮我全文检查”

推荐流程：

1. 先读取全部 `writing-state/`。
2. 检查正文是否与辅助线一致。
3. 再做章节级审读。
4. 输出问题时按优先级排列：
   - 核心发现漂移；
   - 概念术语漂移；
   - 论断缺证据；
   - 机制链条不闭合；
   - 结构顺序不合理；
   - 局部语言问题。

不要从语言润色开始。

## 关键原则

### 1. 辅助线不是额外负担，而是减少返工

没有辅助线时，改一段很快，但全文容易散。  
有辅助线时，前期慢一点，但后期修改更稳定。

### 2. 辅助线要短

每个状态文件都应短而可维护。不要把它写成长篇笔记。

推荐：

```text
一句话核心发现：1 页以内
概念术语表：表格为主
逐段细纲：短句 topic sentence
论断证据表：表格为主
```

### 3. 辅助线要可更新

辅助线不是一次性定稿。论文推进后，它必须更新。

如果正文变化但辅助线不变，辅助线会变成旧地图。

### 4. 辅助线优先级高于局部润色

当正文局部好听但偏离核心发现时，应服从辅助线。  
当辅助线本身错了，先改辅助线，再改正文。

## 最终目标

升级后的 `econ-write-modular` 应该支持这样一种工作方式：

```text
先搭辅助线
再写正文
边写边更新辅助线
用辅助线做全文审读
再用 examples 提升中文表达
```

最终它不只是一个“经济学写作指南”，而是一个“经济学论文施工系统”。

它应帮助 Codex 和作者共同回答：

1. 本文唯一核心发现是什么？
2. 所有章节是否都服务这个发现？
3. 核心术语是否一致？
4. 理论机制、变量、结果是否对齐？
5. 每个强论断是否有证据？
6. 每段是否有明确 topic sentence？
7. 审稿人最可能质疑什么？

这些问题解决后，正文写作才真正稳。
