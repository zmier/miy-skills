# J-260502：econ-write-modular 升级规划

## 一句话目标

把 `econ-write-modular` 从“原始 `econ-write` 的中文模块化拆分版”，升级为一个更适合中文经济学论文写作的“原则 + 中文语境经验 + 已发表论文 examples”的范例驱动型 skill。

## 当前状态

`econ-write-modular` 目前已经完成了第一阶段工作：

1. 保留原始 `econ-write` 的主要内容。
2. 将长篇 `SKILL.md` 拆成多个 `references/*.md`。
3. 将拆分后的文件翻译为中文。
4. 将 reference 文件名改为中文并加序号。
5. 软链到 `.codex/skills`，可作为 Codex skill 调用。

当前版本的优点是：经济学写作原则完整，涵盖摘要、引言、模型、数据、结论、风格、表图、实证规则、现代实证实践、论文结构、审读清单等。

当前版本的不足是：它仍主要是“原则型指南”，还缺少中文经济学论文中的真实写法样例、章节模板、段落功能模式和本土期刊语境下的经验沉淀。

## 参照对象

可以参考 `research-paper-writing-zh` 的结构：

```text
SKILL.md
references/
  00_摘要写作指南.md
  01_引言写作指南.md
  ...
  examples/
    00_示例库索引.md
    abstract/
    introduction/
    method/
```

它的关键优势不是内容领域，而是产品结构：

1. 主 `SKILL.md` 很薄，只负责路由。
2. `references/` 按章节组织写作指南。
3. `references/examples/` 存放模板、句式、段落模式和示例。
4. 每个 examples 文件服务于一个具体写作动作。
5. skill 调用时可以只加载相关指南和示例，而不是一次读取全部内容。

因此，`econ-write-modular` 的升级方向不是照搬计算机论文写作内容，而是借鉴它的组织方式。

## 核心困惑

这次升级要解决的真实问题是：

> 如何把一批已发表中文经济学论文 PDF 转化成可复用的写作经验，而不是简单把论文原文塞进 skill？

具体包括三层：

1. **结构层**：examples 应该如何放置、命名、排序，如何与现有 `references/` 对应。
2. **抽取层**：如何从 PDF 中提取“写法模式”，而不是照搬内容。
3. **使用层**：Codex 调用 skill 时，应如何根据任务读取对应经验和 examples。

## 设计原则

### 1. 不推翻原版，只增补中文经验层

原始 `econ-write` 的内容质量很高，应继续作为底层原则。

新增内容应定位为：

- 中文经济学论文写作习惯；
- 中文期刊语境中的章节组织；
- 已发表中文论文的段落功能模式；
- 适合中文论文的可复用表达框架；
- 中文语境中需要避免的套话、政策腔和概念漂移。

### 2. examples 放在 `references/examples/`

为了与 `research-paper-writing-zh` 保持一致，建议在 `econ-write-modular` 下新增：

```text
references/
  examples/
    00_示例库索引.md
    abstract/
    introduction/
    literature-review/
    theory-mechanism/
    data/
    identification/
    results/
    robustness/
    heterogeneity/
    mechanism-test/
    conclusion/
    referee-response/
```

`examples/` 不放顶层，原因是：

1. 它们本质上是 reference 的支撑材料。
2. Codex 可以按章节指南进一步选择 examples。
3. 目录结构与 `research-paper-writing-zh` 一致，便于维护。

### 3. 从论文中抽取“模式”，不复制“内容”

已发表 PDF 应主要用于提炼：

- 段落功能；
- 论证顺序；
- 研究问题进入方式；
- 政策背景如何落到可检验问题；
- 文献综述如何组织“已有研究 -> 不足 -> 本文贡献”；
- 实证结果如何解释系数、方向、量级、机制；
- 稳健性和异质性如何写成论证，而不是罗列表格；
- 中文论文中自然、克制、可复用的表达方式。

不应把论文长段落原文放入 skill。若需要保留例句，应使用短句或结构化改写，并标注为“写法模式”，而不是“可复制句子”。

本次补充的关键判断：

- 杨子晖第二章可抽象为“三段机制综述 + 一段研究空白”。
- 文献综述段不是作者罗列，而是“机制方向 + 代表文献 + 机制边界”。
- 争议型机制段适合写成“观点 A -> 边界 -> 观点 B”；单向机制段适合拆成若干子渠道。
- 研究空白段必须逐项承接前文机制综述，并用对象、方法和问题推出本文设计。
- 如果本文 X-Y 关系本身是研究空白，不能虚构“已有研究表明 X 影响 Y”的共识；应写相邻文献分别从若干机制线索提供基础。
- 本文核心发现标签不能作为已有文献综述主题，只能在理论假设或结果部分作为预测/发现出口。

## PDF 转化流程

每篇已发表中文论文 PDF 不直接进入 skill，而是经过五步转化。

### 第一步：建立论文清单

为每篇 PDF 记录基本信息：

```text
论文标题
作者
期刊
年份
研究领域
研究方法
论文类型：应用实证 / 理论 / 结构模型 / 政策评估 / 描述性研究
适合抽取的章节：摘要 / 引言 / 文献综述 / 结果 / 结论
```

### 第二步：章节切分

按章节提取文本：

```text
摘要
引言
文献综述
理论分析 / 机制分析
数据来源与变量
模型设定 / 识别策略
实证结果
稳健性检验
异质性分析
机制检验
结论与政策建议
```

### 第三步：段落功能标注

对每个有价值段落标注其功能，而不是只摘录内容。

示例：

```text
段落位置：引言第 2 段
段落功能：从现实案例过渡到研究问题
结构模式：具体事件 -> 影响范围 -> 机制疑问 -> 本文问题
可复用场景：用于风险传染、产业链冲击、金融约束类文章
注意事项：案例不能太长，最后必须落到可检验问题
```

### 第四步：抽取写法模式

把原段落转化为可复用模板：

```text
模式名称：现实冲击进入研究问题
结构：
1. 说明近期现实冲击或制度变化。
2. 指出它影响了哪些主体或环节。
3. 提出仍不清楚的传导机制。
4. 收束为本文研究问题。

句式骨架：
近年来，[现实事件/制度变化] 对 [对象] 产生了显著影响。
这一冲击不仅体现在 [直接影响]，还可能经由 [机制渠道] 进一步影响 [结果变量]。
然而，现有研究对 [具体机制/边界条件] 的解释仍不充分。
本文据此考察 [X] 如何通过 [M] 影响 [Y]。
```

### 第五步：写入 examples

每个 examples 文件应包含：

```text
# 示例类型名称

## 适用场景

## 结构模式

## 句式骨架

## 来自中文论文的写法观察

## 使用注意

## 不建议写法
```

如果使用原文短句，必须控制长度，并以“短例句”形式呈现，不放长段落。

## examples 文件设计

每个 examples 文件不要只是“好句摘抄”，而应回答四个问题：

1. 这个写法解决什么写作问题？
2. 它的段落结构是什么？
3. 它可以迁移到哪些经济学论文场景？
4. 使用时容易出现什么问题？

推荐模板：

```markdown
# 00_政策背景进入研究问题

## 适用场景

用于引言开头从政策背景、现实冲击或制度变化进入研究问题。

## 段落功能

将宏观背景收束为一个可检验的经济学问题。

## 结构模式

1. 背景或冲击。
2. 影响对象。
3. 传导机制或矛盾。
4. 本文研究问题。

## 句式骨架

近年来，[背景/冲击] 使 [对象] 面临 [变化]。
这一变化可能通过 [机制] 影响 [结果]。
然而，关于 [机制/边界/效应] 的经验证据仍不充分。
本文利用 [数据/方法/冲击]，考察 [X] 对 [Y] 的影响。

## 使用注意

- 政策背景不能替代研究问题。
- 不要连续堆多个政策文件。
- 最后一两句必须落到变量、机制或识别对象。
```

## 质量控制

### 1. 防止照抄

每条从论文中抽取的内容都应转化为：

- 结构模式；
- 段落功能；
- 句式骨架；
- 使用提醒；
- 常见误区。

避免保存长段原文。

### 2. 防止期刊腔

中文论文常见问题：

- 政策背景过长；
- “具有重要意义”重复出现；
- 贡献写成空泛评价；
- 文献综述堆作者；
- 结果段只说显著，不解释量级；
- 政策建议超过实证证据。

examples 应同时记录“可借鉴写法”和“不建议写法”。

### 3. 防止概念漂移

每个章节经验文件都应提醒：

- 核心概念只使用一个主术语；
- 变量名、机制名、模型对象保持一致；
- 不要在同一篇文章中混用相近但未定义的概念。

### 4. 防止 examples 过细碎

一个 examples 文件应服务一个可复用写作动作。不要为每篇论文建一个 example 文件。

更好的组织方式是：

```text
按写作功能建文件，而不是按论文建文件。
```

## 第一轮实施计划

### 阶段 1：搭建 examples 架构

创建：

```text
references/examples/
references/examples/introduction/
references/examples/results/
references/examples/robustness/
references/examples/conclusion/
```

先写 `00_示例库索引.md`，只放目录说明和使用规则。

### 阶段 2：选取 5-8 篇中文论文试点

优先选：

- 发表在经济学/金融学中文核心期刊；
- 与当前研究方向相关；
- 引言、实证结果、机制检验写得比较规范；
- PDF 文本可提取质量较好。

### 阶段 3：先做引言 examples

引言最值得优先做，因为它决定论文主线。

优先抽取三类：

1. 政策背景进入研究问题。
2. 现实案例进入机制问题。
3. 文献缺口进入本文贡献。

### 阶段 4：再做实证结果 examples

重点抽取：

1. 基准结果如何解释。
2. 稳健性检验如何写。
3. 异质性分析如何写。
4. 机制检验如何写。

### 阶段 5：更新 SKILL.md 路由

当新增 reference 和 examples 稳定后，再把它们写进主 `SKILL.md` 的路由规则。

## 最终目标形态

理想中的 `econ-write-modular` 应该具备三层能力：

1. **原理层**：继承 `econ-write` 的高质量经济学写作原则。
2. **中文经验层**：总结中文经济学论文在引言、文献综述、实证结果、机制检验、政策含义中的真实写法。
3. **examples 层**：基于已发表中文论文提炼可复用模板，让 Codex 能按具体场景调用范例。

最终使用效果应是：

> 当用户给出一段中文经济学论文，Codex 不仅知道 Cochrane/Head/Bellemare 的一般原则，还知道中文经济学期刊中“政策背景如何收束为研究问题”“实证结果如何写得像论文而不是表格说明”“机制检验如何避免空泛解释”。

这才是这个 skill 的下一阶段价值。
