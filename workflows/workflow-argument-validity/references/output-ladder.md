# 输出阶梯

## 目的

根据任务深度选择输出，不把所有任务都做成完整报告。

## 阶梯

| 层级 | 输出 | 适用场景 |
|---|---|---|
| L1 | 最小箭头审计 | 用户只问某个推理是否成立 |
| L2 | 论证树草图 | 需要看结构，但还不写正式意见 |
| L3 | Mermaid + 节点/箭头表 | 审稿、写作自审、复杂论效题 |
| L4 | 断点分析段 / assumption-impact 段 / question-impact 段 | 需要可直接写入文章、GRE Argument 或审稿意见 |
| L5 | 完整论效题文章 / GRE Argument essay / 审稿意见 / 自审报告 | 需要最终交付文本 |

## 选择规则

- 时间短或问题局部：L1-L2；
- 需要协作和追溯：L3；
- 需要写作输出：L4；
- 需要交付：L5。

## 输出纪律

- L1 也必须说明箭头；
- L3 以后必须有节点和箭头 ID；
- L4 以后必须用克制语言；
- GRE Argument 的 L4/L5 必须按题目指令写出 `assumption -> arrow -> impact if false` 或 `question -> target arrow -> yes/no impact`，不能只列假设或问题；
- L5 必须符合目标场景格式。

## 质量阶梯

论证分析输出的质量不只看“指出了几个问题”，还看是否响应任务、抓住关键箭头并说明影响。

| 层级 | 判断标准 | 常见问题 |
|---|---|---|
| 优秀 | 紧扣任务指令；抓住关键箭头；解释假设、问题或证据如何影响根结论；组织清楚 | 少量问题但分析有力 |
| 合格 | 找到相关断点并有基本解释；能回扣结论；组织大体清楚 | 展开不够深入，影响链偏短 |
| 偏弱 | 只列问题或术语；部分偏离任务；对问题答案的影响说不清 | 有疑问清单，但缺 implication |
| 不合格 | 复述原文、表达个人观点、接受作者逻辑或误读任务 | 没有真正审查 A -> B |

L4/L5 输出前自检：

```text
我是否按题目要求输出 assumptions / questions / evidence / alternatives？
每个问题是否绑定了具体箭头？
我是否说明了不同答案或假设失败时，上层结论如何变弱？
我是否把自己的观点替代成了论证分析？
我是否只是贴了谬误名词？
```
