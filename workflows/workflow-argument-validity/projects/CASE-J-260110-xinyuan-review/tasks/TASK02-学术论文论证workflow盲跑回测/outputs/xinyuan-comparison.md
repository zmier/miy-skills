## 对 workflow 的反哺点

### 1. 抽树阶段要强制展开到表格、脚注、变量定义和样本规则

仅抽：

```text
样本设计 -> DID 识别可信
```

不够。应展开为：

```text
剔除规则
+ 事件窗口
+ 行业重叠事件处理
+ 事件公司是否保留
+ POST 编码
+ 聚类层级
-> 样本和识别设计可信
```

### 2. 选点不能把多个硬问题压成一个“大类问题”

盲跑 I3 把样本、聚类、POST、稳健性合在一起，导致杀伤力下降。更好的写法应拆成：

```text
样本选择偏差
聚类层级错误风险
POST 时间结构不匹配
稳健性没有回应核心威胁
```

这些都可以同属“识别可信度”，但在审稿意见中应分别展开。

### 3. 机制审计要检查“同一概念跨章节是否稳定”

欣媛最强的一点是发现：

```text
需要声誉机制时，作者强调披露行为的信号价值；
需要解释异质性不显著时，又淡化披露内容的信息含量。
```

这不是普通的机制代理问题，而是 storyline premise consistency。

### 4. spillover paper 需要专门检查 direct-effect baseline

如果论文声称：

```text
事件公司行为 -> 同行模仿 / 同行改善
```

则应检查：

```text
事件公司自己是否改善？
事件公司自己是否获得收益？
同行为什么要模仿？
```

### 5. 最终写作前需要 reporting-integrity pass

表注错误、标准误/t 值标注、显著性星号、样本量变化、图表样本不一致，可能不是主论证树问题，但会影响审稿意见的可信度和完整度。

## 下一步建议

对 academic paper line 来说，下一步不是立刻写最终审稿意见，而是升级两处：
