## 3. 来源对话中的核心洞见

### 3.1 从“锋利句子”到“命题化核心发现”

最初的一句话核心发现曾被写成：

```text
专业基金经理也会受有限注意力影响；大众媒体报道会把股票推入他们的买入视野，并损害其投资表现。
```

用户指出，更锋利的版本是：

```text
基金经理受“有限注意力”影响越大，表现越差。
```

随后进一步辨析发现，这句话虽然锋利，但可能跳过了论文的存在性 claim。更完整的形式逻辑还原版应为：

```text
基金经理受“有限注意力”影响；
并且，如果基金经理受“有限注意力”影响越大，那么其投资表现越差。
```

该句的逻辑结构是：

```text
A 且 B

A = 基金经理受有限注意力影响。
B = 如果基金经理受有限注意力影响越大，那么其投资表现越差。
```

其中：

- A 是直言命题；
- B 是假言命题；
- A 且 B 构成联言命题。

### 3.2 “凭什么？”是阅读入口，不是缺陷

一句话核心发现应是一个简短有力的断言，让读者自然追问：

```text
凭什么？
```

后续 Agenda 再承接这个追问：

- 凭什么这么说？ -> 主 X / 主 Y / 代理变量；
- 怎么证明？ -> identification / empirical design；
- 为什么是这个机制？ -> mechanism / alternative explanations；
- 还可能是什么？ -> robustness / boundary conditions；
- 对当前项目有什么用？ -> transfer / route mapping。

### 3.3 摘要是核心命题的默认锚点

一句话核心发现应优先从 abstract 提炼，再用 introduction / contribution / conclusion 校准。表格、系数、稳健性和识别细节主要用于回答“凭什么”，不是第一句 claim 的默认来源。

### 3.4 形式逻辑为核心，论文写作术语为辅助

论文写作和研究设计中常见：

```text
existence claim / descriptive claim
effect / consequence / causal claim
mechanism claim
heterogeneity / boundary claim
contribution / gap claim
```

这些术语有用，但不稳定，因课程、学科和传统而异。更稳妥的主轴应是形式逻辑：

```text
直言命题
假言命题
联言命题
选言命题
简单命题
复合命题
```

论文写作术语只能作为第二层功能标签，不能替代命题化检查。

### 3.5 假言命题的反驳条件

对于假言命题：

```text
A -> B
```

有效反驳形态是：

```text
A 且 非B
```

单纯 `非A` 不能反驳 `A -> B`。这一点对 `argument-arrow-audit` 和 `argument-issue-selection` 特别重要：不是所有看起来相反的材料都能削弱目标 claim，必须判断它是否构成对该命题形态的有效反例。

## 4. 与现有 workflow-argument-validity 的契合点

现有 workflow 已经有多处与本洞见天然契合。

### 4.1 父层核心问题已经是 A -> B

父入口明确：

```text
作者当前给出的论据、方法、数据、事实或例子
是否足以推出作者声称的结论
```

验箭头层也明确：

```text
作者用 A 推出 B；
A 是否足以推出 B？
```

这说明本 workflow 的底层哲学已经接近形式逻辑。新增规则不是推翻现有架构，而是把“B 必须先是可判断真假的命题”显式化。

### 4.2 抽树层已有 claim / evidence boundary

`claim-vs-evidence-boundary.md` 已定义：

```text
claim = 作者要让读者相信的判断
evidence = 支撑判断的可定位、可核查材料
```

并提出判别：

```text
能问“为什么？” -> claim
能问“在哪里 / 哪张表 / 哪个数 / 哪篇文献？” -> evidence
```

本轮洞见可进一步补充：

```text
claim 不仅要能问“为什么”，还必须能还原为形式逻辑视角下的简单或复合命题。
```

### 4.3 学术论文 X2 已要求“具体核心发现”

父层和学术抽树子 Skill 均要求：

```text
X2 必须写成具体核心发现；
不能写成“作者做出来了”“核心发现成立”。
```

当前规则主要用 X/M/Y/Y2 结构约束 X2。命题化规则可作为更上位的质量门：

```text
X/M/Y/Y2 是论文写作 / 研究设计层结构；
命题化是形式逻辑层结构。
```

建议未来将 X2 输出改为：

```text
X2_full_logical_restoration:
X2_readable_compressed_version:
proposition_type:
research_function_labels:
```

### 4.4 验箭头层已有条件关系、概念关系和断点分类

`arrow-audit-core.md` 已有：

- condition-confusion；
- hidden-premise-missing；
- causal-leap；
- concept-mismatch；
- alternative-explanation；
- overclaim。

这些都可承接命题化规则。但目前它主要从断点类型出发，还没有要求在审计前先标注 `to_node` 的命题类型。

## 5. 现有 workflow 的缺口

### 5.1 节点尚未被要求是“命题”

`node-arrow-model.md` 定义了 root / middle-claim / subclaim / evidence / implicit-premise，但没有显式要求：

```text
每个 claim node 必须是可判断真假的命题；
不能只是主题、对象、研究场景、模块名或任务标签。
```

这会导致后续箭头审计时，`A -> B` 中的 B 可能不是严格命题，而只是“机制检验”“变量构造”“贡献成立”这类标签。此时验箭头容易退化为模块 checklist。

### 5.2 一句话核心发现缺少形式逻辑完整还原版

现有学术抽树要求：

```text
一句话核心发现；
X/M/Y/Y2；
X1/X2/Y。
```

但没有要求：

```text
形式逻辑完整还原版；
可读压缩版；
命题类型；
复合命题拆分。
```

结果是 X2 可能虽然“具体”，但仍混合了 claim、proxy、evidence 和 mechanism 展开。

### 5.3 反驳有效性尚未按命题形态区分

验箭头当前强在 “A 是否足以推出 B”，但对于不同 B 的逻辑形态，还没有明确说明有效削弱方式。例如：

```text
若 B 是假言命题 A -> C，有效反驳应寻找 A 且 非C；
非A 只是说明前件未发生，不能直接反驳 A -> C。
```

这会影响：

- arrow audit 中的 break 判断；
- issue selection 中的 priority；
- review writing 中“为什么这是真问题”的解释。

### 5.4 论文写作功能标签与逻辑形式标签尚未分层

现有学术 adapter 里有很多研究设计功能标签：

```text
gap -> contribution
construct -> measure
model/result -> causal claim
mechanism test -> mechanism claim
result -> contribution
```

这些很有用，但如果不先还原命题形式，可能让 `claim` 变成论文写作模块，而不是形式逻辑判断对象。

## 10. 风险与边界

### 10.1 风险：把形式逻辑规则写得过重

考试型或快速任务不能因为命题化要求变得过慢。应允许：

```text
quick proposition check
```

而不是 full logical formalization。

### 10.2 风险：把论文写作功能标签完全抛弃

不能只留下直言 / 假言 / 联言 / 选言。学术审稿仍需要：

```text
construct-measure
identification-causal
gap-contribution
mechanism-evidence
result-contribution
```

正确做法是双层结构：

```text
第一层：形式逻辑命题结构；
第二层：论文写作 / 研究设计功能标签。
```

### 10.3 风险：误把“形式逻辑完整还原版”当最终可读输出

完整还原版用于保证思维清楚；用户界面或审稿段落可使用可读压缩版。两者都应保留，但使用场景不同。

## 11. 建议最终规则草案

可作为后续提升到 reference 的草案：

```text
论证树中的关键 claim node，尤其是 root claim、X2、一句话核心发现和主要 middle claim，必须能被还原为形式逻辑视角下的简单命题或复合命题。

命题化是第一层；论文写作 / 研究设计术语是第二层辅助标签。

若核心发现包含多个 claim，不得为了“一句话”强行删除；应判断它是否是联言命题、选言命题或嵌套假言命题。

对于假言命题 A -> B，有效反驳形态是 A 且 非B；单纯 非A 不能直接反驳该假言命题。

抽树阶段负责命题化核心发现；验箭头阶段负责判断 evidence / subclaim 是否足以推出该命题；选点阶段负责选择能有效削弱目标命题的断点。
```
