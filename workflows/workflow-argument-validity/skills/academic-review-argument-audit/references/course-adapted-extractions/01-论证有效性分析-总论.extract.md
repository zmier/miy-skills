# 01 论证有效性分析：总论提取

## 一句话提炼

论证有效性分析的核心不是评价结论本身对不对，而是检查“论据是否足以推出结论”，也就是检查论证箭头是否成立。

## 课程中的关键方法点

| 方法点 | 课程含义 | 可迁移价值 |
|---|---|---|
| 有效性看箭头 | 论据能够支持结论，论证才有效；不能支持，论证无效 | 审稿时不能只看作者结论是否“可能正确”，要看文本证据、模型、数据、识别是否足以支撑作者声称 |
| 少评论，多分析 | 评论只是说“不成立”；分析要说明为什么推不出 | 审稿意见不能只写“识别不足”“变量不清”，必须解释断点在哪里 |
| 命题点在论证上 | 主要采分点通常在论证箭头，少量在核心概念 | 审稿的核心问题应优先落在“贡献链/因果链/变量链”的断裂处，而不是泛泛挑表达 |
| 核心概念敏感 | 论点里的概念是核心概念 | 审稿时优先检查标题、摘要、引言贡献、结论中的大概念是否被正文变量真正承接 |
| 不数漏洞个数 | 关键不是找几个问题，而是覆盖几组论证 | 审稿任务不能机械追求“列 5 条 major concerns”，而要覆盖论文主要贡献链的关键箭头 |
| 先看结构，不先陷入语义 | 第一遍阅读应找结论、论据和结构关键词 | 快速通读和论证审查应先还原作者的“声称链条”，再进入细节理解 |
| 标点和结构词是入口 | 先看句号旁，再看逗号旁的结构关键词 | 可以转化为论文阅读中的定位动作：摘要、引言末段、理论假设、结果小结、结论段的结构词 |
| 找不到源于没看论证 | 读者若只理解意思，容易被材料带着走 | 审稿时若只顺着作者叙事读，会默认作者的概念替换和因果跳跃 |
| 四类训练 | 抓住论证、行文结构、谬误识别、遣词造句 | 可拆成子 Skill：结构还原、漏洞识别、审稿行文、表达压缩 |
| 三个学习瓶颈 | 找不到、说不清、道不尽 | 对应 Skill 风险：遗漏关键断点、解释不够大白话、审稿意见冗长失焦 |

## 可转化为审稿 Skill 的规则

1. 任何“论证有效性审查”先输出作者的核心论证链：

   `论据/观察事实 -> 中间推理 -> 作者结论/贡献声称`

2. 对每个箭头分别判断：

   - 是否存在概念替换；
   - 是否存在证据不足；
   - 是否存在因果跳跃；
   - 是否存在过度外推；
   - 是否存在替代解释未排除；
   - 是否存在宏观概念与微观指标不适配。

3. 审稿意见必须从“评论句”升级为“分析句”：

   - 弱：作者的变量定义不清。
   - 强：作者将 A 作为 B 的代理变量，但 A 只能反映……，未能说明它为什么足以代表 B，因此从 A 的变化推出 B 的改善存在跳跃。

4. 不按“找够几个问题”推进，而按“几组核心论证是否覆盖”推进：

   - 核心发现论证；
   - 理论机制论证；
   - 变量操作化论证；
   - 因果识别论证；
   - 结果到贡献的上升论证。

5. 若发现“读者看不懂”，先判断属于哪类瓶颈：

   - 找不到：没有先还原论证结构；
   - 说不清：没有解释箭头为什么断；
   - 道不尽：没有压缩为一个明确的审稿点。

## 对 workflow-paper-writing-review 的影响

这份课程总论支持新增或强化一个子 Skill：

`argument-validity-audit`

它不替代现有的变量、方法、结果审查，而是作为更底层的“论证链检查器”，在以下环节被调用：

| Workflow 环节 | 调用方式 |
|---|---|
| 快速通读 | 还原作者声称的核心论证链 |
| 文献定位 | 检查 gap -> contribution 的箭头是否成立 |
| 方法识别审查 | 检查 identification -> causal claim 的箭头是否成立 |
| 变量数据审查 | 检查 construct -> proxy/measure 的箭头是否成立 |
| 结果叙事一致性 | 检查 empirical result -> theoretical contribution 的箭头是否成立 |
| 审稿素材组装 | 把“漏洞”写成“概括-质疑-分析-建议”的审稿段落 |

## 后续抽取时要特别关注

后面几讲应重点抽取：

1. “审题”如何识别论点、论据、论证结构；
2. “行文”如何组织段落；
3. “谬误识别”有哪些稳定漏洞类型；
4. “练习方法”如何形成可复用检查清单；
5. 哪些表达模板可以改写为学术审稿意见，而不显得像考试作文。
