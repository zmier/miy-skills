# 论证有效性分析课程总汇总

## 总原则

论证有效性分析的底层能力可以迁移为学术审稿中的“贡献链验收”：

```text
作者声称 C
作者给出论据 A/B
作者依赖中间推理 M
审稿人检查 A/B 是否足以推出 M，M 是否足以推出 C
```

核心不是判断 C 是否可能正确，而是判断作者当前稿件是否已经证明了 C。

## 四个能力模块

| 模块 | 课程说法 | 审稿迁移 |
|---|---|---|
| 抓住论证 | 找论点、论据、箭头 | 还原作者贡献链、因果链、变量链 |
| 行文结构 | 标题、开头、本论、结尾 | summary、major concerns、minor concerns、recommendation |
| 谬误识别 | 概念、因果、样本、类比等 | 审查 gap、机制、识别、数据、结果、叙事 |
| 训练方法 | 初稿、修改、二稿、三稿 | 审稿 draft、修订稿、subAgent 冷读、最终稿 |

## 审稿中的“箭头”清单

| 箭头 | 要审的问题 |
|---|---|
| 文献 gap -> contribution | gap 是否真实、重要、不同于既有研究 |
| 理论前提 -> 机制 | 机制是否完整，是否有反向机制或边界条件 |
| 概念 -> 操作化指标 | 指标是否真能代表概念 |
| X -> Y | 识别策略是否足以支持因果 |
| 结果 -> 结论 | 统计结果是否足以支撑理论上升 |
| 结论 -> 政策/管理启示 | 启示是否超出证据范围 |

## 审稿谬误库

| 课程谬误 | 审稿版本 |
|---|---|
| 概念不一致 | construct mismatch；关键词漂移 |
| 过度推理 | evidence-claim mismatch；相关写成因果 |
| 极化思考 | 机制唯一化；忽略中间状态 |
| 不当假设 | 未说明的识别假设、代理变量假设 |
| 因果问题 | 反向因果、遗漏变量、共同趋势 |
| 以偏概全 | 样本外推、局部结果推广 |
| 数字陷阱 | 样本、均值、比例、量纲解释不足 |
| 手段目的陷阱 | 管理/政策建议不可行或证据不足 |
| 条件陷阱 | 必要/充分条件混用 |
| 不当类比/比较 | 跨层级、跨国家、跨行业外推 |
| 自相矛盾 | 摘要、理论、结果、结论前后不一致 |
| 忽略发展 | 时间结构、滞后、分类清单更新不足 |
| 顾此失彼 | 只讲一种机制，忽略反向机制和成本 |
| 更换衡量标准 | 用不适配指标评价目标概念 |

## 需要写入 argument-validity-audit Skill 的固定输出

1. **核心论证链**

   ```text
   作者实际观察到 A
   作者解释为 B
   作者上升为 C
   当前最可疑的箭头是 ...
   ```

2. **关键词对照表**

   | 位置 | 作者用词 | 实证指标/证据用词 | 是否一致 | 风险 |
   |---|---|---|---|---|

3. **隐含假设表**

   | 箭头 | 隐含假设 | 是否被证明 | 替代解释 |
   |---|---|---|---|

4. **标准匹配表**

   | 被评价对象 | 衡量标准 | 是否适配 | 建议 |
   |---|---|---|---|

5. **审稿段落草稿**

   每条问题必须按：

   ```text
   定位 -> 分析 -> 收尾 -> 修改建议
   ```

## 对当前审稿 workflow 的增量

`argument-validity-audit` 应作为横向子 Skill，被多个步骤调用：

| Workflow 步骤 | 调用方式 |
|---|---|
| TASK03 快速通读 | 还原作者核心贡献链 |
| TASK04 文献定位 | 审 gap -> contribution 是否成立 |
| TASK05 方法识别 | 审 identification -> causal claim 是否成立 |
| TASK06 变量数据 | 审 construct -> measure 是否成立 |
| TASK07 结果叙事 | 审 result -> theory/contribution 是否成立 |
| TASK10 审稿撰写 | 将漏洞写成克制、可读、可执行的审稿段落 |

## 最关键的一句话

审稿 = 逆向验收作者的论证链：不是问作者的结论有没有可能对，而是问作者当前给出的论据、方法和结果，是否已经足以推出他声称的结论。
