# 04 论证有效性分析：行文 2 提取

## 一句话提炼

本论段不是漏洞罗列，而是先做段落规划，再用“组合分析”把同一组论证中的多个断点组织成一个有力段落。

## 关键方法点

| 方法点 | 课程含义 | 可迁移到审稿的价值 |
|---|---|---|
| 段落规划是审题第三步 | 找完箭头后，要决定本论写几段、每段对应哪组论证 | 审稿前要先决定 major concerns 的结构，不要想到哪写到哪 |
| 一组论证可拆成两段 | 如果一组论证太长，或包含多个关键箭头，可分段分析 | 一个论文模块可能拆成两个 concern，如 X 操作化和 Y 操作化分开写 |
| 不要写超长段落 | 超长段落增加读者识别采分点的负担 | 审稿意见每条 concern 应聚焦，避免一段塞进多个不相干问题 |
| 组合分析 | 同一组论证中多个箭头都影响结论，要逐一切断 | 审稿中一个 major concern 可组合多个相关证据，形成更强判断 |
| 逻辑漏洞是手段，不是目的 | 找漏洞是为了说明论点/分论点推不出 | 审稿不是挑刺清单，而是判断作者的贡献链是否成立 |
| 每段三层 | 定位句、分析句、收尾句 | 每条审稿意见要有对象、理由和对核心结论的影响 |
| 定位句要精炼 | 抓话题关键词，不长篇引用原文 | 审稿意见引用原文时只抓关键声称和指标，不整段搬运 |
| 收尾句要戳破窗户纸 | 说明前面的分析如何影响分论点/结论 | 每条 concern 最后要说清楚这对论文结论意味着什么 |

## 可迁移为审稿段落三层

| 层次 | 功能 | 审稿写法 |
|---|---|---|
| 定位 | 告诉读者正在质疑哪条作者论证 | 作者将机器人产品进口作为机器人采用的证据 |
| 分析 | 说明为什么推不出 | 进口只能说明企业购买或接触了相关产品，不能直接说明设备已投入生产、形成自动化能力或改变生产流程 |
| 收尾 | 回到作者结论 | 因此，该指标尚不足以支撑“机器人采用推动产品升级”的强因果表述 |

## 组合分析在审稿中的用法

### 模板

```text
作者从 A 推出 C 的论证至少包含两个需要补强的环节。首先，A 未必能推出 B，因为……。其次，即使 B 成立，也未必能推出 C，因为……。因此，当前证据更稳妥地支持 A 层面的观察，而不足以支持 C 层面的贡献声称。
```

### 迁移到当前审稿场景

```text
作者从“机器人相关产品进口增加”推到“机器人采用”，再推到“出口产品结构升级”。这一链条至少有两个断点：首先，进口数据未必能说明企业实际采用机器人；其次，即使存在机器人采用，某一产品清单中的出口增加也未必等同于企业层面的产品结构升级。因此，当前发现与作者的上升表述之间仍需要额外论证。
```

## 对 Skill 的要求

`argument-validity-audit` 应强制输出：

1. 每组论证对应哪条审稿 concern；
2. 是否需要组合分析；
3. 组合分析包含哪些箭头；
4. 每个箭头的“论据词 -> 结论词”对照；
5. 最后一句如何回到作者核心结论。

## 后续注意

课程反复强调：不要把“找漏洞”当终点。审稿 Skill 也要避免输出一堆孤立质疑点，而要把质疑点组织成“为什么作者核心结论尚未被证明”的结构。
