# 05 论证有效性分析：行文 3 提取

## 一句话提炼

一个好段落的核心是“定位清楚、分析一针见血、收尾回到结论”；定位句和收尾句可以灵活省略，但定位功能和回扣功能不能丢。

## 关键方法点

| 方法点 | 课程含义 | 可迁移到审稿的价值 |
|---|---|---|
| 分析标志词 | 用“因为、如果、也可能、况且、即使、此外”等提示分析关系 | 审稿意见要显式标出因果、让步、并列和递进，降低读者理解成本 |
| 组合分析连接词 | 递进、让步、并列三类连接词组织多个断点 | 一个 concern 中多条理由要有清楚关系，不要堆句子 |
| 定位句可省，定位功能不可省 | 可直接用话题关键词进入分析 | 审稿意见可不写长背景，但必须让读者知道在说哪条作者声称 |
| 收尾句可省，回扣功能不可省 | 若分析句已经指向分论点，可省；否则必须补 | 审稿段落必须说明该问题如何影响贡献/结论/推荐意见 |
| 分析深度不靠字数 | 精炼、一针见血比冗长更有效 | 中文版审稿意见要避免把技术问题写成长绕句 |
| 不要滥用术语 | 术语不能替代分析 | “内生性”“构念效度”“过度推理”后面必须解释具体断点 |
| 不要诉诸个人观点 | “我认为”不是理由 | 审稿应基于文本、模型、数据和推理，而非个人偏好 |

## 审稿写作中的连接词库

| 逻辑关系 | 中文 | 英文 |
|---|---|---|
| 分析原因 | 因为；这是因为 | because; this is because |
| 条件反驳 | 如果；若 | if; if this is the case |
| 替代可能 | 也可能；另一种可能是 | another possibility is; it may also be that |
| 让步 | 即使；就算 | even if; even assuming that |
| 递进 | 况且；进一步说 | moreover; more importantly |
| 并列 | 此外；同时 | in addition; also |
| 收尾 | 因此；所以；这意味着 | therefore; this means that |

## 可迁移为审稿段落模板

```text
作者将 A 解释为 B。因为 A 还可能反映 A1 或 A2，这一解释并不唯一。即使 A 确实部分反映 B，作者仍需说明 B 如何进一步推出 C；目前稿件尚未排除 D 这一替代解释。因此，这一结果更适合被表述为 A 与 Y 的相关发现，而不是 B 导致 C 的因果结论。
```

## 中文版可读性规则

1. 技术术语必须落到大白话解释：

   - 不只写“存在构念错配”；
   - 要写“作者想讨论的是企业是否真正采用机器人，但实证指标直接看到的是机器人相关产品进口，两者不是同一件事”。

2. 不要没头没尾地提背景：

   - 弱：“以及 2001 年之后出现的新产品如何处理。”
   - 强：“由于作者的新产品分类依赖既有产品清单，需要说明 2001 年之后才出现、且不在原始清单中的产品如何被识别和归类。”

3. 每个技术句后面检查：

   - 读者知道 A 是什么吗？
   - 读者知道为什么 A 会影响结论吗？
   - 读者知道作者应该怎么改吗？

## 对 Skill 的要求

`argument-validity-audit` 和 `final-review-draft` 应加入二次修订：

| 检查项 | 说明 |
|---|---|
| 定位功能 | 每条意见是否能看出对应作者哪句话/哪张表/哪项指标 |
| 分析功能 | 是否解释了为什么推不出 |
| 回扣功能 | 是否说明对核心结论或审稿判断的影响 |
| 连接功能 | 让步、递进、并列是否清楚 |
| 可读性 | 中文是否比英文更清楚，而不是更绕 |
