# 03 论证有效性分析：行文 1 提取

## 一句话提炼

行文不是套话堆砌，而是用稳定结构承载分析：标题表明质疑对象，开头概括论证并表达分寸感，本论留给真正分析，结尾收束判断。

## 课程中的关键方法点

| 方法点 | 课程含义 | 可迁移到审稿的价值 |
|---|---|---|
| 标题应质疑论点关键词 | 标题不能写成文体名、不能提出自己的正向观点，宜围绕材料结论作质疑 | 审稿意见标题/major concern 小标题应直接指向作者的核心声称，而非泛泛写“方法问题” |
| 不支持原论证，也不直接判死刑 | 用疑问或商榷方式表达质疑 | 审稿语言应克制：指出证据不足，而不是断言作者一定错 |
| 全文结构要稳定 | 标题、开头、若干本论段、结尾，各自承担不同任务 | 审稿报告也要分层：summary、major concerns、minor concerns、recommendation |
| 开头两层 | 概括材料 + 表达质疑 | 审稿报告开头应先还原作者声称，再说明主要疑虑 |
| 论据复杂则概括，不展开 | 开头不应长篇抄材料，节省空间给分析 | 审稿意见的 summary 不宜复述过多细节，重点应留给 concerns |
| 简约意识 | 用最简练语言表达，避免机会成本过高 | 审稿写作要避免“看起来很努力但没有增量”的段落 |
| 结尾两层 | 总结自己的分析 + 再次表达质疑/建议 | 给编辑意见应回到证据能否支撑结论，以及是否需要重大修改 |
| 术语不是核心 | 本论少堆术语，结尾可适度概括 | 审稿意见不应堆“内生性、外部有效性、construct validity”等术语，而要解释具体断点 |
| 标点和结构词是路标 | 结构词、破折号等帮助读者快速读懂 | 审稿意见要用清楚的转折、因果、限定语，帮助编辑和作者定位问题 |
| 本论措辞要帮忙不添乱 | 用善意、克制、中性的语言 | 审稿意见要专业、可执行，避免情绪化或羞辱性表达 |
| 写不能提高，改才能提高 | 关键在写后对照规则修订 | 审稿 draft 应设置二次修订：技术准确性修订 + 可读性/语气修订 |

## 可迁移为审稿写作原则

### 1. 小标题要指向“被质疑的箭头”

弱标题：

```text
Identification issue
Variable issue
Robustness issue
```

强标题：

```text
Robot imports are not yet shown to represent robot adoption
Exported products in a list are not yet shown to represent firm-level product upgrading
The IV strategy does not yet rule out pre-existing firm upgrading trends
```

中文版可写成：

```text
机器人进口尚不能直接等同于机器人采用
产品清单中的出口增加尚不能直接代表企业层面的产品升级
工具变量设计尚未充分排除企业既有升级趋势
```

### 2. 开头要做“概括 + 质疑”

审稿报告开头可采用：

```text
本文试图说明：X 会通过 M 影响 Y，并据此声称对 Z 文献作出贡献。这个问题本身重要，数据也有潜在价值；但当前稿件的关键论证链仍不够稳固，尤其是 X 的操作化、Y 的概念适配、识别策略和结果上升表述之间尚未完全闭合。
```

注意这里不是说“作者错了”，而是说“当前论证链尚未稳固”。

### 3. 每条 major concern 的段落结构

从 03 的“开头/本论/结尾分工”可抽象出每条审稿意见的四层：

| 层次 | 功能 | 写法 |
|---|---|---|
| 1. 概括作者论证 | 先公平还原 | 作者将 A 作为 B 的证据，并据此推出 C |
| 2. 表达质疑 | 指出可商榷处 | 这一推理目前仍不充分 |
| 3. 展开分析 | 解释为什么 | 因为 A 只能说明……，但 B 还要求…… |
| 4. 给出建议 | 可执行修改 | 作者需要补充……，或降低结论表述 |

### 4. 语言要“有分寸”

推荐用语：

| 中文 | 英文 |
|---|---|
| 尚不足以支持 | does not yet fully support |
| 有待进一步说明 | requires further clarification |
| 这一推理仍显跳跃 | this inferential step remains underdeveloped |
| 可能存在概念层面的错位 | may involve a construct mismatch |
| 需要更清楚地区分 | should more clearly distinguish |
| 当前证据更直接支持的是 | the evidence more directly supports |
| 作者可以考虑降低表述强度 | the authors may consider tempering the claim |

避免用语：

| 中文 | 英文 |
|---|---|
| 荒谬 | absurd |
| 毫无道理 | groundless |
| 显然错误 | obviously wrong |
| 完全无效 | completely invalid |
| 作者不懂 | the authors fail to understand |

## 对 argument-validity-audit 的规则增量

1. **输出不只要找漏洞，还要给出可写入审稿意见的段落。**

   每个漏洞必须同时生成：

   - 结构还原；
   - 质疑句；
   - 分析句；
   - 修改建议句。

2. **禁止只写标签式批评。**

   不允许停在：

   ```text
   存在内生性问题。
   存在变量测量问题。
   存在过度推断。
   ```

   必须展开为：

   ```text
   作者从 A 推出 C，但 A 只说明……。若要支持 C，还需证明 B；当前稿件尚未排除 D，因此该结论需要进一步限定或补充检验。
   ```

3. **审稿意见要优先保留分析空间。**

   Summary、背景复述、礼貌性评价要短；major concerns 中的“为什么推不出”要充分。

4. **设置二次修订动作。**

   Draft 完成后必须检查：

   - 是否有空泛复述；
   - 是否有情绪化措辞；
   - 是否每条 concern 都解释了“为什么”；
   - 是否每条 concern 都有可执行建议；
   - 中文版是否比英文版更容易懂，而不是更绕。

## 对现有 workflow 的影响

| Workflow 环节 | 应补动作 |
|---|---|
| TASK10 审稿最终稿撰写 | 增加“行文克制性与可读性修订” |

## 可形成的审稿段落模板

### 模板 A：概念错位

```text
作者将 A 作为 B 的经验证据，并进一步据此讨论 C。然而，A 与 B 并不完全等同：A 更直接反映的是……，而 B 至少还包含……。因此，若作者希望维持关于 C 的较强表述，需要进一步说明 A 为什么能够有效代表 B；否则，更稳妥的做法是将结论限定为 A 层面的发现。
```

### Template A: Construct Mismatch

```text
The manuscript uses A as empirical evidence for B and then links this result to C. However, A and B are not equivalent: A more directly captures ..., whereas B also requires .... Therefore, if the authors wish to maintain the stronger claim about C, they need to explain why A is a valid proxy for B; otherwise, the conclusion should be narrowed to the level directly supported by A.
```

### 模板 B：证据不足以支持上升表述

```text
当前结果更直接支持的是 A 与 B 之间的关系，而不是作者在引言和结论中提出的 C。这个上升表述需要额外论证：作者需要说明从 A/B 到 C 之间的中间机制、边界条件和替代解释。否则，该发现的贡献应被表述得更谨慎。
```

### Template B: Overstated Claim

```text
The current evidence more directly supports the relationship between A and B, rather than the broader claim C advanced in the introduction and conclusion. This stronger claim requires additional justification, including the intermediate mechanism, boundary conditions, and alternative explanations linking A/B to C. Otherwise, the contribution should be stated more cautiously.
```

## 后续要继续观察

03 只讲到了标题、开头、结尾和总体措辞。本论段内部如何展开，应该会在行文 2/3 中继续讲。后续重点看：

1. 一个漏洞段应该写几层；
2. 如何从“评论”升级为“分析”；
3. 如何压缩字数但不牺牲解释；
4. 是否有固定句式可改造成审稿段落模板。
