# 10 论证有效性分析：练习方法提取

## 一句话提炼

训练不是多写几篇就完事，而是按“审题 -> 初稿 -> 对照解析 -> 修改 -> 二稿/三稿”的循环，把结构识别、漏洞表达和语言精炼磨成习惯。

## 课程中的练习流程

| 步骤 | 课程方法 | 可迁移到 Skill 工程 |
|---|---|---|
| 1. 限定材料范围 | 先练高质量真题，不乱做材料 | Skill 抽取要基于高质量资料，不把单篇案例硬编码成规则 |
| 2. 先练审题 | 先还原论证结构 | 审稿先还原作者贡献链 |
| 3. 写电子版 | 方便统计、修改、比较 | 审稿 TASK 全部留 md 版本和修订记录 |
| 4. 卡住可看解析 | 不要空耗时间 | 审稿中可查前序 TASK、文献和参考资料，不装作闭卷 |
| 5. 初稿不要要求过高 | 先表达清楚全面 | 审稿初稿先抓问题，不急着完美 |
| 6. 改中进步 | 写只是给改提供材料 | TASK10 必须包含修订轮次 |
| 7. 看范文和批改 | 从好例子和坏例子中学习 | 用 subAgent/读者审查发现可读性问题 |
| 8. 写第二版 | 吸收后重写，而不是抄 | final-review-draft 需要二版对照 |
| 9. 隔一段时间写第三版 | 温故知新 | 重要审稿意见可做最终冷读 |
| 10. 互相批改 | 看受众反应 | subAgent log 记录读者误读、背景缺口、术语不明 |

## 对审稿 workflow 的启发

审稿意见不应一次生成即结束，而应至少有三轮：

1. **结构轮**：确认作者论证链和 major concerns 是否覆盖核心断点；
2. **分析轮**：确认每条 concern 是否解释了为什么推不出；
3. **读者轮**：确认中文版/英文版是否读得懂，是否有没头没尾的术语和背景跳跃。

## 对 Skill 的要求

`final-review-draft` 和 `argument-validity-audit` 应明确：

| 输出 | 必须保留 |
|---|---|
| 初稿 | 结构完整，问题充分 |
| 修订稿 | 精炼表达、补足背景、降低术语密度 |
| 对照说明 | 说明修订解决了哪些问题 |
| subAgent log | 记录读者审查、技术审查、论证有效性审查发现的问题 |

## 可迁移的一句话原则

写是为了得到可修改的材料；真正提高质量的是改。审稿 workflow 也一样：第一稿发现问题，第二稿讲清楚问题，第三稿让编辑和作者愿意读、读得懂、知道怎么改。
