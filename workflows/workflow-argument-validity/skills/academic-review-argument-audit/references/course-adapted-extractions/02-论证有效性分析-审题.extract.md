# 02 论证有效性分析：审题提取

## 一句话提炼

审题的核心是先抓论证结构，而不是先理解故事内容；通过论点位置、推理方式、结构关键词和标点，快速还原“谁在支持谁”。

## 课程中的关键方法点

| 方法点 | 课程含义 | 可迁移到审稿的价值 |
|---|---|---|
| 论点有位置规律 | 论点可能前置、中置、后置；总论点常在开头段末句，总结论可能在末段 | 快速通读论文时优先检查摘要结论句、引言末段贡献句、结论段总结句是否一致 |
| 三种推理方法 | 直推、合推、分推；复杂论证也是三者组合 | 论文贡献链可拆成单链、多证据合推、一个证据支持多个结论三类 |
| 总分总/总分结构 | 标准化文本常有总论点、分论点、总结论 | 学术论文也常是“总贡献 -> 多个分贡献/假设/结果 -> 总结上升”的结构 |
| 先看结构关键词 | 通过“因此、总之、其实、因为、据报道、表明”等判断句间关系 | 论文中应优先抓“we find, therefore, suggest, imply, contribute, because, consistent with”等结构信号 |
| 先句号后逗号 | 先看句子之间关系，再看分句内部关系 | 审稿阅读先抓段落层面的论证，再进入句内术语和指标细节 |
| 对比论点与结论关键词 | 若有开头论点和末尾结论，要对比主谓宾/话题关键词 | 检查论文是否从“机器人组件进口”滑到“机器人采用”，从“出口某类产品”滑到“产品结构升级” |
| 技术动作防止漏掉偷换概念 | 不按步骤读，容易忘记前文论点，漏掉后文概念替换 | Skill 应强制做“声称词 vs 证据词”对照 |
| 不要被内容好奇心带跑 | 看到“据报道”等先判定其为论据，不急着读故事 | 审稿时先判断一段是理论、证据、机制、结果还是外推，再决定细读深度 |
| 复杂结构要画在旁边 | 简单箭头可直接标在原文，复杂合推/分推要写成结构图 | 对复杂论文可产出 Mermaid/DAG/论证链图，而不是只写段落摘要 |
| 结构与表达相互支撑 | 好的表达依赖标点、结构词和层次 | 审稿意见写作也必须让读者看见“问题从哪里来、为什么成立、作者该怎么改” |

## 审题动作可迁移为审稿动作

### 1. 先找论文的总论点和总结论

在论文中对应检查：

| 课程审题对象 | 论文审稿对象 |
|---|---|
| 第一段最后一句 | 摘要最后一句、引言开头的问题定义、引言末段贡献声明 |
| 最后一段第一个词 | 结论段第一句、结论段总结性词汇 |
| 论点与结论话题关键词 | 标题、摘要、引言贡献、结论中的核心概念是否一致 |

审稿 Skill 应强制输出：

| 位置 | 作者原始表述 | 核心关键词 | 是否一致 | 备注 |
|---|---|---|---|---|
| 标题/摘要 |  |  |  |  |
| 引言贡献 |  |  |  |  |
| 结论 |  |  |  |  |

### 2. 再拆每组分论证

每个主要部分都要拆成：

`论据 A -> 中间判断 B -> 分结论 C`

或：

`论据 A + 论据 B -> 分结论 C`

或：

`论据 A -> 分结论 B / 分结论 C`

在论文中对应：

| 论文模块 | 应拆的论证 |
|---|---|
| 理论与假设 | 理论前提 -> 机制 -> 假设 |
| 变量定义 | 理论构念 -> 操作化指标 -> 可解释性 |
| 识别策略 | 设计/工具变量/固定效应 -> 排除替代解释 -> 因果结论 |
| 结果部分 | 回归系数 -> 统计/经济意义 -> 理论解释 |
| 贡献部分 | 结果 -> gap 填补 -> 学术贡献 |

### 3. 做“话题关键词对照”

这一讲对我们之前的困惑特别有用：很多审稿问题不是因为作者没结果，而是作者在不同位置使用的关键词不一样。

可固定成如下检查：

| 层级 | 作者使用的词 | 实际证据/指标中的词 | 可能问题 |
|---|---|---|---|
| X 声称 | robot adoption | imports of robot products/components | 机器人进口是否等于机器人采用 |
| Y 声称 | export product sophistication / product upgrading | exports of products in a classification/list | 国贸产品层级指标能否代表企业产品结构升级 |
| 因果声称 | leads to / improves | association under empirical model | 因果箭头是否被识别策略支撑 |
| 贡献声称 | fills gap / first evidence | specific empirical context | 是否过度外推 |

## 对 argument-validity-audit 的具体规则

1. **读论文不能直接摘要内容，必须先还原结构。**

   最小输出是：

   ```text
   作者想证明：C
   作者用来证明 C 的材料：A/B/D
   作者隐含的中间推理：A/B/D -> C
   当前最可疑的箭头：...
   ```

2. **优先检查首尾一致性。**

   若摘要、引言和结论中的关键词不一致，应记录为潜在“概念漂移”。

3. **每个 major concern 绑定一组论证。**

   不写孤立问题，而写成：

   ```text
   作者从 A 推出 C，但这一推理依赖 B。当前稿件没有充分说明 B，因此 A 尚不足以支持 C。
   ```

4. **遇到复杂论证必须画结构。**

   可用如下 Mermaid 草图：

   ```mermaid
   flowchart LR
     A[观察事实/数据结果] --> B[作者中间解释]
     D[理论或文献依据] --> B
     B --> C[作者贡献/结论]
     E[替代解释] -.挑战.-> B
   ```

5. **用结构词和标点防止遗漏。**

   对论文中的“therefore, thus, suggests, implies, consistent with, because, due to, as a result”等词做重点定位；这些位置往往是作者把证据上升为结论的地方。

## 可形成的审稿输出模板

### 结构还原段

> 作者的核心论证可以还原为：基于 A，作者认为 B，进而得出 C。这个论证的关键不在于 C 是否可能成立，而在于 A 是否足以支持 B，以及 B 是否足以推出 C。

### 概念漂移段

> 稿件在不同位置使用的核心概念并不完全一致。引言和结论强调 C，但实证部分实际衡量的是 A。除非作者进一步说明 A 为什么能够有效代表 C，否则从 A 的变化推出 C 的改善存在概念层面的跳跃。

### 合推不足段

> 作者似乎依赖 A 和 B 共同支持 C。然而，A 只能说明……，B 只能说明……；二者合在一起仍未排除 D 这一替代解释。因此，当前证据尚不足以支撑作者对 C 的强表述。

## 对现有 workflow 的影响

这一讲要求我们在多个 TASK/SKILL 中补一个统一动作：**先做论证结构还原，再做模块审查。**

| Workflow 环节 | 应补动作 |
|---|---|
| TASK03 快速通读 | 输出总论点、总结论、分论证链 |
| TASK04 文献定位 | 把 gap -> contribution 画成箭头，检查是否偷换 |
| TASK05 方法识别 | 把 identification -> causal claim 画成箭头 |
| TASK07 结果叙事一致性 | 对比摘要/引言/结果/结论关键词，检查首尾概念漂移 |
| TASK10 审稿意见撰写 | 每条 major concern 必须绑定一组论证结构 |

## 后续要吸收进 Skill 的一句话原则

先看结构，再看意思；先找箭头，再找漏洞；先确认作者到底在证明什么，再判断他有没有证明成。
