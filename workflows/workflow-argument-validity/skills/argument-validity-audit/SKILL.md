# Argument Validity Audit

## 目标

检查“论据是否足以推出结论”，而不是判断结论本身是否可能正确。

```text
论据 A
-> 中间推理 M
-> 结论 C
```

本 Skill 要回答：

- A 是否真的支持 M；
- M 是否真的推出 C；
- 作者是否把较弱证据写成较强结论；
- 是否存在概念、范围、层级、因果、样本或标准错配；
- 如何用克制、清楚、可执行的语言写出问题。

## 输入

- 待审论证文本；
- 或已抽取的论点、论据、结论；
- 或领域 adapter 提供的材料，例如论文贡献链、变量定义、方法说明、结果表、审稿草稿。
- 若输入来自 GRE Analyze an Argument 或类似任务，必须同时读取题目指令，判断它要求分析 assumptions、evidence needed、questions、alternative explanations、recommendation、prediction 还是 conclusion。

## 流程

1. 还原论证链：

   ```text
   作者想证明：C
   作者使用的论据：A/B
   隐含中间推理：A/B -> M -> C
   ```

2. 关键词对照：

   | 位置 | 原词 | 概括词 | 层级 / 范围 | 备注 |
   |---|---|---|---|---|
   | 论据 |  |  |  |  |
   | 中间推理 |  |  |  |  |
   | 结论 |  |  |  |  |

3. 检查隐含假设：

   | 箭头 | 隐含假设 | 是否被证明 | 如果不成立的影响 | 替代解释 |
   |---|---|---|---|---|

   每个假设都必须写成影响链：

   ```text
   作者需要假设 H
   H 支撑 A -> B
   如果 H 不成立，B / C / root claim 会变弱、需要降调或断裂
   需要证据 E 才能补强 H
   ```

4. 若任务要求列出 questions / evidence needed / alternative explanations，先选择对应输出框架：

   | 指令 | 输出框架 |
   |---|---|
   | assumptions / hidden premises | `assumption -> supporting arrow -> impact if false` |
   | questions that need to be answered | `question -> target arrow -> yes/no or alternative-answer impact` |
   | evidence needed | `evidence -> which arrow it would strengthen/weaken -> why` |
   | alternative explanations | `observed fact -> rival mechanism -> impact on author's explanation` |

5. 识别断点：

   | 断点类型 | 判断问题 |
   |---|---|
   | 概念不一致 | 论据和结论是否使用了不同概念 |
   | 过度推理 | 论据是否只能支持更弱结论 |
   | 因果跳跃 | 是否把相关、共现或时间顺序写成因果 |
   | 以偏概全 | 样本、时间、地区、群体是否被外推 |
   | 数字陷阱 | 平均数、比例、增长率、份额、指数是否被误读 |
   | 不当假设 | 结论是否依赖未证明前提 |
   | 替代解释 | 同一事实是否还可能由其他机制解释 |
   | 不当比较 / 类比 | 比较对象是否同层级、同口径、同条件 |
   | 自相矛盾 | 文中不同位置是否互相冲突 |
   | 忽略发展 | 是否用静态事实直接推出动态状态 |
   | 顾此失彼 | 是否只看一面，忽略反向机制或代价 |
   | 更换衡量标准 | 评价对象与实际标准是否匹配 |

6. 审查数字、百分比和统计材料：

   - 不把数字当作自动证据；
   - 检查基数、口径、时间标准、样本范围和指标含义；
   - 区分比例变化和绝对数量变化；
   - 检查统计差异是否可能由替代解释造成；
   - 说明该数字支撑的是较弱结论、较强结论，还是根本不能支撑作者结论。

7. 做组合分析：

   - 若一个论证链有多个断点，按箭头顺序分析；
   - 若同一个箭头可从多个角度切断，选择最影响结论的 1-3 个角度；
   - 不为了展示术语而堆叠问题。
   - 若任务是问题型输出，不只列问题；每个问题都要说明不同答案如何改变结论可信度。

8. 写成分析段落：

   ```text
   定位：作者将 A 作为 C 的依据。
   分析：但 A 更直接说明的是 A1，而 C 还要求 B 成立；当前文本尚未证明 B。
   收尾：因此，A 尚不足以支持 C。
   建议：作者需要补充 B 的证据，或将结论降调为 A1 层面的发现。
   ```

   若任务要求 assumptions，使用：

   ```text
   假设：作者需要 H 成立。
   作用：H 支撑 A -> B。
   影响：若 H 不成立，B/C/root claim 会变弱或断裂。
   补强：需要 E 说明 H 确实成立。
   ```

   若任务要求 questions，使用：

   ```text
   问题：需要回答 Q。
   箭头：Q 检验 A -> B。
   影响：若答案为 yes，论证如何增强；若答案为 no 或存在替代答案，论证如何削弱。
   ```

## 输出

必须至少包含：

1. 核心论证链；
2. 最可疑箭头；
3. 断点解释；
4. 更稳妥的结论边界；
5. 可写入目标文本的段落草稿。

若任务带有特定指令，还必须包含对应结构：

- `assumption -> arrow -> impact if false`;
- 或 `question -> target arrow -> yes/no impact`;
- 或 `evidence -> strengthen/weaken arrow`;
- 或 `alternative explanation -> rival mechanism -> impact`。

## 语言规则

- 少写术语，多解释为什么推不出。
- 用“尚不足以支持”“有待进一步说明”“这一推理仍显跳跃”等克制措辞。
- 避免“荒谬”“毫无道理”“显然错误”等情绪化措辞。
- 对读者可能不知道的背景，补一句桥接解释。
- 不把自己的观点、政策偏好或事实判断写成替代答案；先评价作者论证是否推出。
- 不用“可能有问题”结束分析；要说明这个问题如何削弱哪条箭头。

## 完成标准

- 论证链已还原；
- 每个主要断点都绑定具体箭头；
- 隐含假设或待回答问题已说明对上层结论的影响；
- 数字、比例或统计材料已检查基数、口径、样本和指标含义；
- 没有把孤立术语当分析；
- 输出能被领域 adapter 改写为审稿意见、报告意见或学习笔记；
- 不把个案判断写成通用规则。
