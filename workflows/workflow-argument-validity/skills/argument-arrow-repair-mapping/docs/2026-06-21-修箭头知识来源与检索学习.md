# 2026-06-21 修箭头知识来源与检索学习

## 索引说明

这段对话记录的是 `argument-arrow-repair-mapping` 建立后的关键反思：

```text
修箭头不是靠模型凭空知道所有领域实验；
也不是把单篇真实审稿意见硬编码成答案；
而是：
断箭头 -> 识别知识缺口 -> 检索/深读同类高质量文献 -> 生成本案 repair map -> 可迁移部分沉淀为 repair menu。
```

核心问题：

- `materials-device-repair-menu.md` 算不算“小抄”？
- 如果下一篇换领域，模型还会不会？
- 是否可以通过检索文献来临时建立 repair knowledge？
- 摘要是否足够，还是必须看原文 / 图表 / 补充材料？

以下为原文记录。

## 原文记录

**用户：**

不是，你「materials-device-repair-menu.md」里面写的还不算小抄吗？🤣

**Codex：**

哈哈哈，对，你抓得很准。严格说，`materials-device-repair-menu.md` **当然算“小抄”**。

更准确的说法应该是：

这次没有给 subAgent **这篇稿子的真实审稿人答案小抄**，但给了它一个**通用材料/器件审稿修复菜单小抄**。所以这不是测试“模型凭空知道多少实验”，而是测试：

```text
断箭头 + 通用 repair menu
-> 能不能把问题映射成像样的补实验/补分析方案
```

因此这次 UAT 的含义要降级理解：

- 不能证明 subAgent 自己天然知道该补 `zeta / EIS / EDS`。
- 能证明 `academic-arrow-repair-mapping + materials-device-repair-menu` 这套 Skill 作为“外挂知识”有效。
- 能证明我们这个 repair menu 没白写，subAgent 能读懂、能路由、能绑定到具体箭头，而不是泛泛抄菜单。

所以更严谨的结论是：

```text
Skill-assisted repair mapping: pass
pure-model reviewer-like experiment suggestion: not tested
```

如果要真测“完全不带小抄”，下一轮应该禁读 `materials-device-repair-menu.md`，只让它读父 Skill + audit outputs，看它能补出什么。大概率会掉到“泛泛补机制实验/稳定性实验/SOTA 表”的水平。

**用户：**

那怎么办🤣就没有什么办法，比如去检索一些文献什么的，也可以不用小抄就能提出来方案吗？那这篇学了会了，下一篇怎么办呢？不还是不会吗？

**Codex：**

有办法，而且你这个问题正中要害：**不能靠“背小抄”，要靠“遇到新领域时，临时建立可验证的小抄”**。

我会把它分成三层：

**1. 通用逻辑层：不需要小抄**
这个我们已经有了。任何论文都先问：

```text
A 真的能推出 B 吗？
如果推不出，是概念错配、测量不足、机制跳跃、比较口径不同、样本外推，还是应用过度上升？
```

这层老王论效就能解决。它告诉我们“哪里断”。

**2. 领域修复层：需要临时学习**
问题是“怎么补”。材料论文要补 zeta/EIS/EDS；经济学要补 pre-trend、weak IV F-stat、placebo、mechanism test；医学要补 randomization、blinding、endpoint、adverse events。这个不能幻想模型天然都懂。

所以正确流程应该是：

```text
断箭头
-> 判断 arrow type
-> 生成 evidence need
-> 检索同领域高质量论文/综述/真实审稿意见/方法指南
-> 抽取“别人怎么证明这类箭头”
-> 形成本案 repair map
-> 把可迁移部分沉淀成 repair menu candidate
```

也就是说，下一篇新领域不是“不会”，而是先跑一个 **repair-knowledge-learning** 步骤。

**3. 固化层：从临时知识变成 Skill**
这篇水伏学到的 `zeta / EIS / EDS / BET / artificial sweat`，不是只为这篇服务。它应该沉淀成“材料/器件实验论文 repair menu”。下次同类论文就能直接用；如果遇到新类型，比如医学 RCT、AI 模型论文、金融实证论文，再临时学习，再沉淀新的 menu。

所以真正稳的流程应该变成：

```text
验箭头
-> 修复知识缺口识别
-> 查文献/查方法/查同类顶刊怎么证明
-> 生成临时 repair menu
-> 生成本案 arrow-repair-map
-> case 后反哺通用 menu
```

这意味着我们现在还缺一个子 Skill，可能叫：

```text
academic-repair-knowledge-learning
```

它专门解决：

```text
我不知道这类箭头该补什么实验/分析
-> 去哪里查
-> 查哪些关键词
-> 看综述还是顶刊原文
-> 如何从文献中抽出 repair pattern
-> 哪些只是本案知识，哪些能沉淀成 menu
```

所以你说“下一篇怎么办”非常对。答案不是让模型硬想，而是让 workflow 学会：

```text
不知道 -> 标记 knowledge gap -> 检索学习 -> 生成临时小抄 -> 本案使用 -> 可迁移则沉淀
```

这个才是可持续的。

**用户：**

哎！这就有点意思啦！这些思路，检索的文献的摘要中会有吗？还是必须得看原文才行呢？

**Codex：**

有些会在摘要里，有些必须看原文，尤其是“补什么实验/怎么证明箭头”这种，**摘要通常不够**。

可以这样分：

**摘要大概率够用**
摘要通常能帮我们判断：

```text
这个领域常研究什么问题；
常用什么材料/方法/指标；
别人声称的核心机制是什么；
常见结果指标是什么；
这篇文章是不是同类 SOTA / comparator；
gap 是否真的大概存在。
```

比如摘要里可能会写：

```text
we demonstrate a wearable hydrovoltaic generator...
high current density...
stable output under simulated sweat...
```

这能告诉我们“别人也在做这类事”。

**摘要可能提到，但不稳定**
有些方法词会出现在摘要里：

```text
zeta potential
electrochemical impedance spectroscopy
contact angle
finite element simulation
ablation study
placebo test
event-study design
```

如果作者把它当卖点，摘要会有；如果只是常规补充实验/稳健性，摘要往往不写。

**必须看原文/图表/补充材料**
真正决定“这类箭头怎么补”的东西，经常藏在：

```text
Methods
Results and Discussion
Figure captions
Supplementary Information
Reviewer response / rebuttal
Appendix
Robustness checks
Control experiments
Benchmark tables
```

比如：

```text
EDL 机制到底用 zeta 还是 EIS 还是 ion mapping；
SOTA 表具体列哪些指标；
稳定性测 600s、8h、24h 还是几周；
人工汗液用哪些成分；
经济学 IV 的 first-stage F、exclusion restriction 怎么报；
DID 的 parallel trend 怎么画；
AI 论文 ablation / baseline / dataset split 怎么做。
```

这些摘要通常不够。

所以 workflow 应该分两级：

```text
Level 1: 摘要扫描
目标：识别领域、同类论文、常见 claim / metric / method。
产物：candidate repair routes。

Level 2: 原文/图表/补充材料深读
目标：提取“别人怎么证明这根箭头”的具体证据包。
产物：repair pattern / evidence standard。
```

大白话说：摘要像“菜单名”，原文才是“菜谱”。  
我们要知道“该补什么菜”，摘要够一点；但要知道“这道菜怎么做才像样”，多数要看原文。
