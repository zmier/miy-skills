# 2026-06-21 小抄分层与修箭头模式

## 背景

在 TASK04 UAT 后，我们发现 `materials-device-repair-menu.md` 本质上是“小抄”。这不是问题本身；问题在于必须区分小抄类型、适用边界和知识来源。

## 小抄分层

```text
抽树小抄 = 结构框架
拆/验箭头小抄 = 通用逻辑谬误与断点框架
修箭头小抄 = 领域证据标准 / 实验菜单
```

风险从低到高：

```text
结构框架 < 通用断点框架 < 领域 repair menu
```

### 抽树小抄

抽树里的小抄主要是结构框架：

```text
evidence -> subclaim -> middle claim -> root claim
X1：问题有意义
X2：作者证明了具体核心发现
Y：贡献成立 / 值得发表
```

它不是告诉 agent 这篇论文哪里错，而是告诉 agent 论文通常可以如何读成 claim/evidence 结构。

### 验箭头小抄

验箭头里的小抄是通用断点库：

```text
concept-mismatch
measurement-mismatch
causal-leap
scope-expansion
sample-weakness
comparison-mismatch
overclaim
evidence-qc-gap
```

它告诉 agent 如何判断 `A -> B` 是否推得动，但一般不会告诉 agent 某领域具体要补什么实验或分析。

### 修箭头小抄

修箭头里的小抄是领域证据标准，例如：

```text
characterization -> mechanism
可能需要 zeta potential / EIS / EDS ion mapping
```

这最接近答案，因此必须标注来源、边界和迁移状态。

## 修箭头模式

`argument-arrow-repair-mapping` 应使用三种模式：

```text
mode: menu-assisted
mode: learning-required
mode: hybrid
```

### menu-assisted

已有领域 repair menu 覆盖当前断点。允许使用，但必须写：

```text
knowledge_source: existing-menu
source_reference_or_learning_route: references/xxx-menu.md
```

### learning-required

新领域、新方法或用户要求不用既有小抄。必须先输出：

```text
repair-knowledge-learning-plan.md
case-repair-menu.md
```

再生成本案 `arrow-repair-map.md`。

### hybrid

部分断点用已有 menu，部分断点进入检索学习。默认使用此模式。

## 摘要与原文分工

摘要通常够用：

```text
领域是否活跃；
同类 claim 是否存在；
常用 metric / material / method 名称；
潜在 comparator。
```

原文 / 图表 / 补充材料通常必须看：

```text
具体控制实验；
图表指标组合；
benchmark table 字段；
稳健性组合；
实验条件、时间、浓度、负载、样本规则；
方法假设和验收标准。
```

因此：

```text
摘要像菜单名；
原文才是菜谱。
```

## 沉淀规则

单篇 case 学到的 repair pattern 不能直接进入 stable menu。先标：

```text
case-only
candidate-general
stable-menu
```

只有多篇文献、权威方法来源或多个真实审稿 case 反复出现时，才升为 stable menu。
