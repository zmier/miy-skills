# C++ 对象语义卡点

## 定位

本 reference 属于 `analyze-android-native-static`。

它处理的不是“补 C++ 基础课”，而是：native 静态分析中出现 C++ 对象、虚表、继承、RTTI 或异常痕迹时，如何避免把对象派发误判成普通函数指针或稳定算法入口。

## 典型红灯

| 红灯 | 优先判断 | 看雪资料入口 |
| --- | --- | --- |
| Hex-Rays 出现 `(*(*obj + offset))(...)` 一类多层间接调用 | 可能是虚函数调用，不要直接把伪代码里的函数指针当固定入口 | 看雪第3章 课时13-14 |
| 同一对象偏移在多个函数中反复出现 | 可能是对象字段、vptr 或结构体成员 | 看雪第3章 课时13、15 |
| 看到 vtable、typeinfo、RTTI 字符串或析构函数痕迹 | 先恢复类层次和真实实现函数，再设计 Hook | 看雪第3章 课时14-16 |
| 构造/析构、异常路径影响控制流 | 静态结论只作结构候选，真实执行路径仍需运行时证据 | 看雪第3章 课时16 |
| C++ 语义不清导致 Hook 点不稳定 | 回到 xref、vtable slot、调用者偏移和运行时调用链交叉验证 | 看雪第3章 课时13-16 |

## 推荐动作

```text
发现 C++ 对象/虚表痕迹
→ 标记 this 指针、vptr、vtable slot 和对象字段候选
→ 查构造函数、析构函数、RTTI/typeinfo 字符串和 xref
→ 区分 vtable slot、真实实现函数、包装入口和调用点
→ 用 objdump/IDA 记录调用指令与目标地址类型
→ 需要真实执行时交给 hook-android-native 捕获调用者偏移和参数
```

## 证据边界

- C++ 对象语义只能提高 Hook 候选和调用关系解释质量；
- 静态恢复出的类名、继承关系或 vtable slot 不能单独证明本次请求调用了该实现；
- 真实参数、真实返回值、动态派发结果仍必须由运行时 Hook、Trace 或 fixture 证明；
- 不因看雪课程讲过某种对象布局，就把当前样本的固定偏移写成通用规则。
