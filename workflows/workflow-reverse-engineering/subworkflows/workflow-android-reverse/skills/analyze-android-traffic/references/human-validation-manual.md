# 人类验证操作手册契约

## 生成时机

只在候选矩阵已经形成，且下一项证据需要人类操作 App、读取界面状态或在 Reqable 中执行低频重放时生成。

候选尚未形成时，不得预写具体接口验证步骤；返回采集或候选分析阶段。

## 必备内容

每份 `validation-operation-manual.md` 至少包含：

- 本轮要区分的候选与假设；
- 实验编号 `EXP-*`；
- 实验前业务基线如何读取；
- 人类需要执行的唯一动作；
- AI/MCP 同步记录的请求与响应；
- 等待时间和刷新方式；
- 人类需要报告的原始观察；
- 成功、失败和不确定分别意味着什么；
- 缓存、延迟、并发、自然变化和服务端去重等替代解释；
- 安全次数上限与停止条件。

## 单实验格式

```text
实验编号：
候选编号：
要检验的假设：
实验前基线：
唯一变量：
人类操作：
机器同步动作：
等待与刷新：
人类反馈：
判定规则：
替代解释：
停止条件：
```

## 人机分工

- AI：选择最有信息量的下一实验，准备请求证据，记录响应，更新候选状态。
- 人类：执行界面动作、读取业务显示、报告异常，不解释网络字段。
- AI 不得把预期答案写进操作提示，避免引导人类观察。
- 人类反馈必须原样记入实验日志，再由 AI 分析。

## 迭代规则

每轮优先执行一个最能区分候选的实验。实验结束后：

1. 更新 `experiment-log.md`；
2. 更新候选的“保留、排除、仍不确定”状态；
3. 若已确认，停止生成新手册；
4. 若仍缺证据，只生成下一轮最小实验；
5. 若无法安全验证，降低结论等级并说明限制。
