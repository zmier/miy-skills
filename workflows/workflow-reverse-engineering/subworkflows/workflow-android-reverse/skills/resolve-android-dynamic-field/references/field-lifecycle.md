# 动态字段生命周期

## 分层模型

按返回优先级追踪，而不是直接跳到最深算法：

1. **进程内缓存**：静态变量、单例、对象字段。
2. **应用持久化**：SharedPreferences、数据库、文件、Keystore。
3. **跨位置恢复**：外部存储、系统设置、旧版本迁移。
4. **服务端来源**：注册响应、配置下发、登录态。
5. **本地首次生成**：系统标识、硬件属性、随机数、时间和算法。
6. **规范化与编码**：大小写、过滤、排序、拼接、哈希、异或、Base64、加密。

当前请求通常只触发第 1 或第 2 层。要研究首次生成，必须证明前面各层为空或直接只读调用生成方法，不能仅凭当前返回值猜测。

## 状态变化实验

| 操作 | 主要影响 | 默认策略 |
|---|---|---|
| 重启目标进程 | 清进程缓存 | 可执行，记录前后值 |
| 清特定内存字段 | 单个缓存层 | 仅在明确 Hook 范围内 |
| 删除单个测试偏好键 | 持久化层 | 先备份；仅限授权靶场 |
| 清应用数据 | 全部应用状态 | 破坏性操作，需明确目标 |
| 重装 App | 安装状态与部分存储 | 不能假定等于全新设备 |
| 换设备/系统版本 | 系统与硬件来源 | 作为独立 fixture |

优先使用只读调用、已有新装 fixture 或课堂证据。不要为了“看一眼首次生成”破坏现有环境。

## 来源分支记录

每个分支至少记录：

- 触发条件；
- 原始系统或业务输入；
- 权限和系统版本影响；
- 规范化规则；
- 输出稳定周期；
- 写回位置；
- 与其他字段的共享输入。

## 绑定判断

重点检查：

- 多字段是否共享 Android ID、MAC、账号 ID、安装 UUID 或服务端注册记录；
- 替换一个字段时是否需要同步替换其他字段；
- 值是否要求单请求、单会话、单安装或跨安装稳定；
- 服务端成功是否只是尚未触发延迟风控。
