# 替代输入验证

## 目标

验证一个替代值能否满足当前授权场景，而不把它误认为 App 的真实原值。

## 必填信息

- 原字段及真实值是否已知；
- 替代公式和随机性来源；
- 真实性要求：`functional-equivalent` 或 `app-authentic`；
- 预期绑定：账号、Cookie、设备标识、请求头、历史状态；
- 稳定周期：单请求、单会话、单安装或跨安装；
- 验证范围和未覆盖风险。

## 对比方法

1. 验证长度、字符集、Base64 变体、padding 和可逆性。
2. 将替代值带入参数排序、sign 和正文算法，确认结构闭合。
3. 与真实 fixture 分别执行，明确哪些差异由替代输入引起。
4. 只在授权环境做一次或最低必要次数的行为验证。
5. 若要求跨请求稳定，固定替代值并验证生命周期；不要每次随机。
6. 检查相关字段是否必须共同变化。

## 结论

- 只通过格式或算法组合：保持 `substitute-candidate`。
- 通过当前范围行为与稳定性验证：标记 `substitute-valid`。
- 恢复 App 真实生成规则：标记 `reproducible`。
- 与 App 原值和运行行为交叉验证：标记 `validated`。

网络返回成功不自动证明不存在服务端绑定或后续风控。
