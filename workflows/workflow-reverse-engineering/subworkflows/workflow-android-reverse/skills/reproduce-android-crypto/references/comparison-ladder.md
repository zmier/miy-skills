# 分层比对阶梯

按顺序比较，首个差异就是当前阻塞：

1. 参数 key 集合；
2. key 排序；
3. 空值和字符串格式；
4. 参数明文字节；
5. 盐字节；
6. sign 十六进制；
7. `&sign=` 拼接后的完整明文；
8. Key 与 IV 的原始字节；
9. AES mode 与 padding；
10. 最终密文字节。

不要在最终密文不一致时直接猜 AES；多数错误来自参数顺序、字符集、Key 表示方式或动态配置。

以上完成的是 G1 离线等价。若任务要求真实重发，继续检查：

11. HTTP 方法与 URL；
12. 必要请求头及其与正文动态字段的绑定；
13. Content-Type 与正文原始字节；
14. HTTP 状态；
15. 响应正文和业务码。

第 10 层一致不代表第 15 层必然成功。

G2 前先对 App 原始成功请求执行第 1-10 层重算。若完全一致而第 15 层失败，首差位于显式算法之外，应继续检查 Token/did 时效与绑定、Cookie、TLS/连接态、设备证明或服务端策略。
