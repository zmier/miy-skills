# JNI 地址绑定与防追踪分支

## 定位

本 reference 属于 `map-android-jni`。

它处理的是：Java native 方法与 so 函数之间不是普通静态导出或稳定 RegisterNatives 映射，而是存在地址隐藏、动态绑定、防追踪或反调试干扰。

## 典型红灯

| 红灯 | 可能含义 | 看雪资料入口 |
| --- | --- | --- |
| Java 有 native 声明，但导出表没有 `Java_*` | 动态注册或更复杂绑定 | 看雪第10章 课时15；第13章 课时5 |
| Hook RegisterNatives 事件不完整 | 注册发生过早、符号不稳或被包装 | 看雪第10章 课时15 |
| 映射到的是跳板，不是真实主体 | 函数地址二次跳转或动态解密 | 看雪第13章 课时5-6 |
| PrettyMethod/retval 与 JNINativeMethod 数组不一致 | ART 内部路线与 JNI 表路线存在差异 | 看雪第4章 课时9；第10章 课时15 |
| 运行时地址会变化或访问后释放 | 内存动态释放、防追踪 | 看雪第13章 课时4-6 |
| 目标代码只在短窗口解密、执行后释放 | 短生命周期代码窗口，需要捕获加载/执行/释放时机 | 看雪第13章 课时4 |
| 硬件断点/IDA/Frida 跟踪时行为改变 | 反调试或地址防追踪 | 看雪第13章 课时6 |

## 路线选择

默认仍从低侵入路线开始：

```text
静态导出检查
→ Hook RegisterNatives 读取 JNINativeMethod 数组
→ 反汇编确认入口或跳板
→ Native Hook 验证目标动作执行
```

若红灯出现，再升级：

```text
RegisterNatives 事件缺失或不完整
→ ART PrettyMethod + retval 平行路线
→ linker / JNI_OnLoad / dlsym 生命周期观察
→ 反汇编确认跳板或动态解密代码
→ 必要时硬件断点、IDA Trace 或 Stalker
```

## 短生命周期代码窗口

如果代码存在动态释放、防追踪或执行后擦除，不能只保存“最终地址”：

- 记录加载/解密时机；
- 记录执行窗口；
- 记录释放/擦除时机；
- 区分函数指针、跳板、主体地址和调用点；
- 优先用目标动作最小触发，不扩大 trace 窗口；
- 硬件断点只能作为高侵入确认手段，使用前要记录授权设备、调试器、断点地址和回滚方案。

## Green 边界

- JNI 映射 Green 只证明“Java native 到 so 地址”的绑定；
- 如果入口是跳板，必须继续标记“主体未确认”；
- 如果存在地址防追踪，完成标准至少包括：
  - 捕获绑定时机；
  - 捕获当前运行时 implementation；
  - 若代码短生命周期，捕获加载、执行和释放窗口；
  - 说明地址类型：函数指针、跳板、主体、调用点或返回地址；
  - 通过一次目标动作 Hook 证明该地址实际执行。
