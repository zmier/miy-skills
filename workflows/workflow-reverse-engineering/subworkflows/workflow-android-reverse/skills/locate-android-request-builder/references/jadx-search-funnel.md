# JADX 搜索漏斗

## 搜索次序

1. 完整 Path：`/x/report/click/android2`
2. 去除前导部分：`report/click/android2`
3. 末段：`click/android2`
4. 网络方法名：例如 `reportClick`
5. Content-Type：`application/octet-stream`
6. 已知字段名、常量或 RequestBody 类型

## 工具策略

- 用 `jadx --version` 记录版本；
- 用 CLI 反编译到 TASK 的 `workspace/jadx/`，便于 `rg` 检索和保留证据；
- 用 `.gitignore` 排除反编译产物；
- GUI 只承担人工浏览，不作为唯一证据来源；
- JADX 报告局部错误时，先判断目标类是否成功生成，不因总错误数直接判定失败。

## 每层要回答的问题

| 层级 | 问题 |
|---|---|
| 网络声明 | 方法、注解、Body 类型和拦截器是什么？ |
| 调用点 | 谁调用网络方法，传入什么对象？ |
| Body 构造 | 哪个参数最终成为请求正文？ |
| 明文拼装 | 业务字段在哪里进入 Map、Builder 或序列化对象？ |
| 签名 | sign 的输入、排序、常量和输出是什么？ |
| 编码/加密 | 明文如何变成最终 `byte[]`？ |
| 运行时 | 哪个真实 Java 方法最适合 Hook 输入与输出？ |

## 证据记录

每个命中记录：

- 搜索词；
- 类与方法真实符号；
- JADX 别名（若有）；
- 文件位置；
- 关键调用关系的简短摘录；
- 该命中支持什么结论；
- 尚未排除什么解释。

不要大量复制反编译代码；只保存支撑链路的最小片段和定位。
