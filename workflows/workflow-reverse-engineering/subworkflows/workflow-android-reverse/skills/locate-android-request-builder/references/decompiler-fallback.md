# 反编译器回退阶梯

不要因为课程使用了旧工具就机械复刻工具切换。先判断当前产物是否已经回答问题。

## 保持当前 JADX

满足以下条件时继续：

- 方法体完整；
- 参数、常量、分支和返回值可读；
- Find Usage 能连接上下游；
- 可用 Frida 或固定 fixture 验证关键结论。

## 需要回退的证据

- `Method not decompiled`；
- 明显错误的控制流、类型或异常块；
- Kotlin/Java 伪代码丢失关键循环或字节转换；
- 多 Dex 未加载或目标类缺失；
- Frida 运行结果与伪代码无法解释地冲突。

## 回退顺序

1. 检查 JADX 版本、反编译参数和全部 Dex。
2. 查看 JADX bytecode/Smali。
3. 用另一版 JADX 对单类复核。
4. 用 GDA、JEB 或其他反编译器交叉检查。
5. 以 Smali/字节码和运行时 fixture 作为最终裁决。

工具切换本身不是知识点。报告必须写明原工具缺失了什么，以及新工具补出了什么。
