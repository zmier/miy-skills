# 单变量参数删减法

## 基线

先证明未经修改的副本仍能得到预期响应。基线失效时停止删减，重新采集新鲜样本。

## 单项实验

每个 `MIN-EXP-*` 记录：

1. 基线请求编号；
2. 唯一删除或替换的参数；
3. 修改前后的结构差异；
4. HTTP 状态；
5. 业务码和响应摘要；
6. 业务观察；
7. 结论；
8. 替代解释；
9. 是否恢复基线。

## 三态之外保留第四态

- `必要`：删除后可重复失败，恢复后成功。
- `条件必要`：只在某种登录、设备、时间或字段组合下需要。
- `可删除`：删除后响应和业务结果均保持等价。
- `仍不确定`：响应证据与业务观察不足或相互冲突。

## 成组依赖

单项删减完成后：

1. 从基线复制新请求；
2. 一次删除所有已标记“可删除”的项；
3. 进行一次组合验证；
4. 失败时使用二分回加，寻找隐藏的成组依赖。

## 停止条件

- 达到预设实验次数；
- 出现风控、账号、设备或环境异常；
- 基线请求失效；
- 请求体不透明，无法继续按字段编辑；
- 已定位唯一动态阻塞，应该切换后续 Skill。
