# Android 请求参数归约

## 目标

把一个已成功重放的目标请求逐步缩减为最小可用请求，并用实验而非直觉区分：

- 必要参数；
- 条件必要参数；
- 可删除参数；
- 尚不确定参数；
- 需要后续逆向的动态值。

## 前置条件

开始前确认：

- 需求 TASK 工作区；
- 已确认接口或明确标记的高置信候选；
- 一份成功响应的原始请求副本；
- 可恢复的基线请求；
- 低频实验权限和停止条件；
- 能够观察 HTTP、业务码或授权测试环境中的业务结果。

目标接口尚未收敛时，返回 `analyze-android-traffic`。

## 工作流

1. 保存只读基线请求并分配 `BASE-REQ-*`。
2. 按 `references/parameter-inventory.md` 建立头部、查询参数、表单字段、JSON 字段和不透明正文清单。
3. 先删除明显由协议栈自动生成或与业务无关的低风险头部，再处理应用自定义头部。
4. 每个实验只删除或替换一个参数，分配 `MIN-EXP-*`。
5. 每次实验都从基线副本重新开始，不在上一次删减结果上继续叠加。
6. 按 `references/ablation-method.md` 记录服务器响应、业务码、业务观察和替代解释。
7. 将参数标记为“必要”“条件必要”“可删除”或“仍不确定”。
8. 先得到单参数结论，再对全部“可删除”项做一次组合验证。
9. 输出最小请求 fixture 和动态字段清单。
10. 将第一个真正阻塞复现的动态值路由给 Java、混淆、JNI、Native 或算法复现 Skill。

## 编排交接

由总编排调用时：

- 接收 Mermaid 中的参数必要性红灯和 Green 条件；
- 每次实验只删除或替换一个参数，并从基线重新开始；
- 将必要性结果同步到请求树、字段表和测试矩阵；
- 解开不透明层后，把新字段挂到真实父节点下面；
- 将唯一 `NEXT` 指向当前主路线第一个必要未知叶子，不把全部未知字段同时设为阻塞。

## 不透明请求体

若请求体是 `application/octet-stream`、gRPC、压缩或密文：

- 不得假装可以直接删除其中的业务 `key`；
- 先把正文整体标记为“不可分字段”；
- 可以独立测试整个正文是否必要，但不要发送空正文超过一次；
- 使用课程代码、运行时 Hook 或解码证据恢复明文结构后，再对内部字段做归约；
- 将“正文整体必要”与“正文中的每个字段都必要”严格区分。

## 判断规则

- HTTP 失败或明确缺参错误：支持“必要”，但检查格式损坏或依赖字段。
- HTTP 成功且业务码成功：支持“可删除”，但仍需检查业务结果。
- HTTP 成功但业务无效：标记“条件必要”或“仍不确定”。
- 无即时业务变化：考虑缓存、延迟、去重和自然变化。
- 删除 A 失败、删除 B 失败，不代表 A 与 B 分别必要；可能存在成组约束。
- 只有组合验证成功后，才能发布最小请求。

## 人机协作

需要 Reqable GUI 编辑和重放时，按 `references/human-minimization-manual.md` 生成操作手册。AI 负责安排实验次序和记录响应；人类只执行指定的单项删除，不自行连续试删。

## TASK 写回

至少产出：

- 参数清单 `parameter-inventory.md`；
- 人类操作手册 `minimization-operation-manual.md`；
- 归约实验日志 `minimization-log.md`；
- 最小请求卡 `minimal-request.md`；
- 脱敏 fixture；
- 动态字段与下一 Skill。

原始凭据、设备标识、Cookie、Token 和完整敏感正文不得写入 Markdown。

## 完成标准

- A：所有保留和删除项均有单变量证据，组合后的最小请求仍通过业务验证。
- B：请求结构已最小化，但业务观察受缓存、延迟或环境限制，明确标记限制。
- C：已定位到不可分的不透明正文或动态值，能够说明为什么必须进入后续逆向。

仅凭“删了没报错”不能宣布参数可删除。
