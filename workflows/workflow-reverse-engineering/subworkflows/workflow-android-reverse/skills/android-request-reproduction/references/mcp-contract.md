# MCP 通用契约

把 MCP Server 视为可以替换的工具适配器。

每次调用工具时，先定义：

```yaml
任务意图:
所需能力:
输入产物: []
预期证据:
副作用:
授权范围:
降级方案:
调用结果:
证据角色: primary/confirmatory/exploratory
落盘产物:
资源释放:
```

将返回结果统一整理为：

- **位置**：文件、类/方法、地址、模块或请求；
- **观察**：原始值或工具发现；
- **解释**：当前含义与置信度；
- **来源**：MCP/工具名称及调用方式；
- **下一步**：证据指向的后续操作。

不要把某个 MCP 的私有函数名写入领域决策规则。

## 生命周期

1. 打开数据库或会话前记录输入路径与哈希。
2. 先做最小能力探测，再执行目标查询。
3. 只读分析默认不修改数据库；若修改类型、名称或注释，必须另存并记录。
4. 对话结果要进入 Green，必须整理为 TASK 内的最小报告或机器可读产物。
5. 完成后显式关闭数据库、会话或服务，记录是否成功释放锁。
6. MCP 超时、函数边界缺失或输出过大时，降级为脚本/batch，并把 MCP 标为 `exploratory` 或 `superseded`。
