# 工作流状态

每个 evaluation 或授权任务维护一份独立状态记录。

```yaml
任务_id:
授权范围:
目标应用或fixture:
课程_day:
目标请求:
验收与测试契约:
请求构造台账:
台账完成范围:
以终为始:
  最终可观察结果:
  当前完成声明:
  终点最近变更:
当前主路线:
交付路线:
  R1-运行时Hook:
  R2-Frida-RPC:
  R3-纯外部独立生成:
  R4-组合路线:
测试状态:
  smoke:
  unit: {}
  g1_offline_equivalence:
  g2_controlled_e2e:
  uat:
当前红灯:
  节点或测试_id:
  阻塞原因:
  next_task:
  green条件:
  预期证据:
未解决必要叶子_按路线:
  R1: []
  R2: []
  R3: []
  R4: []
未知输出:
请求样本:
当前阶段:
当前阻塞:
观察: []
假设: []
证据: []
使用的工具: []
路线切换记录: []
完成条件:
复现等级:
环境差异: []
人工判断: []
下一步:
```

先更新“观察”，再提出“假设”。每条证据都要链接到文件、工具结果、类/方法、JNI 签名、模块偏移或 fixture 数值。

`复现等级`可以描述当前阶段；整条 TASK 是否完成必须同时参考请求构造台账，不得只看阶段等级。

`当前红灯`必须与 Mermaid 中唯一 `NEXT` 指向同一对象。两者不一致时，先修正状态，不执行新工具动作。
