# G2 服务端拒绝分层

用于 G1 或原始请求预检接近完成，但受控端到端请求返回非预期 HTTP/业务状态的场景。目标是定位首差层，不把所有失败回滚成算法错误。

## 状态码与常见解释

| 现象 | 首差候选 | 优先实验 |
|---|---|---|
| `401/419` | 登录态、Token 生命周期、Cookie 过期 | 展开前置接口 DAG，检查时效和持久化 |
| `403` | 权限、设备态、IP、UA、风控策略 | 对照原始 App 请求和外部请求的 Header/连接态 |
| `406` | 请求上下文、Header 组合、设备态或服务端策略不接受 | 先拿原始成功请求；若不可得，Hook Header/Body 构造点 |
| `418` 或 CloudWAF 页 | WAF、出口 IP、TLS 指纹、UA、请求频率 | 降低频率，比较 App 内请求与外部请求，记录 WAF request id |
| `2xx` 但空列表 | 业务参数、AB 实验、推荐上下文 | 检查前置接口、关键词、分页、实验桶 |
| `2xx` 但业务码失败 | sign/密文格式对，但上下文或会话不匹配 | 字段消融，比较响应业务码与服务端提示 |
| RPCException `[1009] 访问被拒绝` | 账号态、设备态、频率、权限、风控或上下文不满足 | 立即停止重复探测，记录最近成功样本与拒绝样本，等待冷却后只做单变量最小实验 |
| 将 DID、APDID、apdidToken、authorization、miniwua、Cookie 或签名相关字段改动后从 `1009` 变成 `1006` | 设备态字段束不一致、签名链/登录态/安全 SDK token 绑定被破坏 | 停止随机替换；调用 `resolve-android-dynamic-field` 并读取 `device-state-bundle.md`，优先追字段束读取、持久化和刷新链 |

## 决策规则

1. 若原始 App 请求本身失败，不能把它当作成功 fixture；先解决采集窗口或业务基线。
2. 若 App 内请求成功、外部重放失败，比较 URL、方法、Header、Body 原始字节、TLS/代理/出口和设备态。
3. 若课堂脚本或历史脚本现在返回 WAF/拒绝，把它标为历史路线失效，不强行作为 Green 标准。
4. G1 已通过但 G2 拒绝时，保留 G1 Green，新增运行态/设备态/传输上下文 TASK。
5. 只有当首差回到 sign/密文/字段字节不一致，才回滚算法节点。
6. App 内 RPC 已出现服务端拒绝时，不得继续推进外部 G2 重试；先把拒绝视为采集护栏和路线风险。
7. 对设备态字段束，`1006` 往往比 `1009` 更能说明“替换破坏了一致性”。不要因为某次低频请求偶然成功就宣称 DID/APDID 可随机替换；必须有窗口控制、重复样本和字段束证据。

## 台账写法

在 `request-construction-ledger.md` 中同时记录：

- App 内原始请求状态；
- 外部预检请求状态；
- 服务端拒绝码和响应摘要；
- 当前拒绝层级；
- 下一项最小实验；
- 是否影响 G1、G2、UAT。
