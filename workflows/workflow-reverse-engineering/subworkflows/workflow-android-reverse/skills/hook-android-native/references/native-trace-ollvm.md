# OLLVM / Native Trace 运行时取证路线

## 定位

本 reference 属于 `hook-android-native`，并与 `analyze-android-native-static` 交叉使用。

它解决的是：目标 native 算法已定位到大致函数或窗口，但静态伪代码因为 OLLVM、控制流平坦化、指令替换或虚假控制流而难以直接读懂。

## 典型红灯

| 红灯 | 处理思路 | 看雪资料入口 |
| --- | --- | --- |
| IDA 伪代码巨大且不可读 | 不试图读完混淆，改追输入处理和输出生成 | 看雪第5章 课时9；第1章 课时13-15 |
| 明显是控制流平坦化 | 静态只定位 dispatcher、状态变量和函数窗口，主证据转运行时 trace | 看雪第5章 课时4、9；第1章 课时9-10 |
| 明显是虚假控制流 | 静态识别不可达/噪声分支，不把所有分支都纳入算法复现 | 看雪第5章 课时5、9；第1章 课时12 |
| 明显是指令替换 | 先从输入输出和关键常量建立 oracle，再决定是否逐条还原 | 看雪第5章 课时6、9；第1章 课时11 |
| 明显是字符串加密 | 动态观察运行时解密点、解密后字符串和调用窗口 | 看雪第5章 课时7；第1章 课时7-8 |

| Trace 日志太大 | 限定目标 so、线程、函数 start/end、调用窗口 | 看雪第1章 课时14、16 |
| 输出 buffer 生成链不清 | 从写输出的指令反向追寄存器 | 看雪第1章 课时14 |
| 一个样本复现但不放心 | 批量 fixture 对拍原函数 oracle | 看雪第1章 课时15 |
| OLLVM 反 Frida 检测函数读不懂 | 先恢复观察链，再对检测函数做 trace | 看雪第10章 课时17 |
| 想构造最小 OLLVM 对照样本 | 用 NDK/OLLVM 自己编一个小 so，对比混淆前后差异 | 看雪第5章 课时8 |
| 通用 trace 仍解释不了算法 | 另开专项 TASK，记录为什么通用路线不足，再考虑非通用方法 | 看雪第5章 课时10 |

## OLLVM 分型判断

遇到 OLLVM 迹象时，先分型再决定路线：

| 类型 | 常见表现 | workflow 动作 |
| --- | --- | --- |
| 控制流平坦化 | dispatcher、状态变量、巨大 switch、真实路径被状态机包裹 | 静态只确认函数窗口、状态变量和输出点，主证据转 IDA Trace 或 Stalker |
| 虚假控制流 | 大量看似可达但与输入输出无关的噪声分支 | 不逐条解释所有分支；用运行时路径和输出写入点收束 |
| 指令替换 | 简单操作被展开成不直观的等价指令序列 | 先建立输入输出 oracle，再决定是否还原替换表达式 |
| 字符串加密 | 静态字符串缺失或只见密文表，运行时出现明文 | Hook 解密点或字符串使用点，保存明文、调用者和触发动作 |

若只能判断“伪代码很乱”，不能直接写成 OLLVM Green；至少需要静态形态、运行时路径或工具识别中的一个证据支撑。

## 推荐流程

```text
Native 映射已知
→ hook-android-native 固定同次输入/输出 fixture
→ analyze-android-native-static 确认函数窗口、返回点、调用者
→ 选择 IDA Trace 或 Stalker
→ 从输入读取点或输出写入点追寄存器
→ 写最贴近指令的外部实现
→ 用原 App/native 函数作 oracle 批量对拍
→ 通过后再整理为可读算法
```

## 工具选择

| 情况 | 优先路线 |
| --- | --- |
| 需要 GUI 断点、寄存器、可视化回溯 | IDA Trace |
| 需要脚本化、可复制、自动化记录 | Frida Stalker |
| 只需要入口入参和输出 fixture | 普通 Native Hook |
| Trace 后要快速验证 C 算法 | Frida CModule 或独立 native/CLI |
| 目标函数短且静态可读 | 不必 trace，直接静态 + Hook 对照 |
| 需要理解混淆前后差异 | 构造最小 OLLVM 对照样本，但只作为学习/解释辅助 |
| 通用方法成本失控 | 停止扩大 trace，另开专项 TASK 评估非通用方法 |

## Green 边界

- `observed`：只看到一组输入/输出；
- `hook-available`：能稳定再次取得输入/输出；
- `trace-explained`：已能解释关键输出如何由输入、表或常量生成；
- `reproducible`：外部实现可对固定 fixture 生成一致输出；
- `validated`：多组随机或真实样本与原函数 oracle 对拍一致。

不应把“trace 看起来像”写成算法 Green。
