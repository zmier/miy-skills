# 最小 Native Hook

## 单轮只回答一个问题

先写 Green 条件，例如：

```text
在目标业务函数的一次调用中，按顺序捕获 1 个正文片段和 4 个固定长度片段，
并把最终输出与 App 返回值关联。
```

不要一开始 Hook 全部导出、所有线程和全部加密函数。

## 过滤层级

按需要逐层增加：

1. 目标模块；
2. 函数相对偏移；
3. 调用者模块；
4. 返回地址相对偏移；
5. 线程 ID；
6. 参数长度或结构；
7. 目标动作时间窗口。

## 延迟加载与双边界夹取

- so 未加载时监听 `dlopen/android_dlopen_ext`，按模块名命中后安装一次 Hook。
- 观察 Key/IV 时，Native 侧记录生产字节，Java 侧记录 `SecretKeySpec` 或 `IvParameterSpec` 接收字节。
- 两侧必须使用同一次业务调用、线程或序号关联；相同字节可排除中间表示转换。

## 缓冲区记录

至少保存：

- 参数序号；
- 指针是否为空；
- 声明长度；
- 实际读取长度；
- Hex；
- 可选 UTF-8；
- 调用者偏移；
- 时间戳和调用序号。

读取长度必须设置上限。异常指针应记录错误事件，不能让脚本静默退出。

## 停止条件

- 已取得满足 Green 条件的一组同次 fixture；
- 事件量超出预算，需要收紧过滤；
- App 崩溃或行为发生改变；
- 地址、ABI 或模块哈希与 TASK 不一致。

## 看雪查字典入口

本 reference 只规定最小 Hook 纪律。只有在以下基础动作反复失败时，才把看雪第1章作为补课入口：

- 不清楚模块基址、相对偏移、导出符号与非导出函数的关系；
- Native 参数、返回值、指针和缓冲区读取方式不熟；
- so 延迟加载、`dlopen` 监听、ASLR 或 ARM32 Thumb 位处理导致 Hook 不稳定；
- 已有偏移但最小 Frida Native Hook 脚本无法稳定采集 fixture。
