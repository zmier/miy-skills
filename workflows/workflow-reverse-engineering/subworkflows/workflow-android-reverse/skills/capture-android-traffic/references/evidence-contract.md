# 抓包证据契约

## 输入

- 授权范围
- 设备序列号
- 目标包名
- 目标动作
- 预期域名或请求特征

## 输出

每次采集任务至少记录：

| 字段 | 内容 |
|---|---|
| 时间窗口 | 开始与结束时间，精确到秒 |
| 抓包拓扑 | USB reverse 或局域网、代理地址和端口 |
| 目标范围 | 包名、域名、路径或关键字 |
| Reqable 证据 | 会话筛选条件与请求数量 |
| MCP 证据 | health、ingest 计数、request ID |
| 样本 | 脱敏 HAR 或结构化请求摘要 |
| 结论 | A/B/C 等级、阻塞层和置信度 |
| 恢复动作 | 是否清除 Android 全局代理、停止用户 VPN、移除 `adb reverse` 和关闭临时监听 |

## 状态建议

- 课程或经验中的“抓不到包”没有在当前环境复现：`not-reproduced`。
- 强制转发或备用抓包路径可用，但没有证明它是必需路径：`passed-with-scope`。
- 登录、真实账号、验证码或授权边界阻止继续采集：`blocked-by-boundary`。
- 有连接但无明文：不要标记入口失败，转 CA/Pinning 诊断。
- 无连接：保留代理、reverse、VPN、目标包和动作窗口证据。

## 脱敏

删除或替换：

- `Authorization`、Cookie、Session、设备账号；
- 手机号、邮箱、用户 ID 和定位信息；
- 可直接复用的签名、Token 与完整敏感响应体。

保留字段名称、编码形态、长度和必要的局部结构，以支持后续分析。
