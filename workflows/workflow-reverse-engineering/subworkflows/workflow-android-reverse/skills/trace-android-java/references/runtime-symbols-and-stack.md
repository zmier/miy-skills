# 运行时符号与调用栈

## 先确认真实符号

以下情况不要直接照抄 JADX 左侧文件路径写 Frida：

- JADX 显示 `renamed from Kotlin metadata`；
- Kotlin 顶层函数被反编译成便于阅读的别名；
- 接口静态字段保存真实实现；
- 同名字段和短方法名导致 Frida wrapper 冲突。

处理顺序：

1. 阅读 JADX 注释中的原始类名。
2. 对接口字段用反射读取对象并记录 `getClass().getName()`。
3. 先用最小脚本 `Java.use(realName)` 验证类可加载。
4. 同名冲突时优先 Hook 明确 overload，或改从无冲突的底层方法/持久化入口观察。
5. 在 TASK 日志保存“JADX 可读别名 → 运行时真实符号”映射。

## 何时打印调用栈

适用：

- 已知目标 setter/缓存写入方法，但 Find Usage 结果过多；
- 需要确认本次执行经过哪条调用分支；
- 混淆后多个短方法职责相似；
- 生命周期触发点不明确。

不适用：

- 需要恢复参数的拼装公式；
- 需要知道字段来自哪个 map key；
- 需要获得真实随机字节、时间、Key、IV 或返回字节。

调用栈只证明控制流，不证明数据流。看到上游方法后，仍需用 JADX 阅读赋值逻辑，或在边界 Hook 参数和返回值。

## 最小输出

每个栈事件至少记录：

- 时间；
- 线程；
- 真实类名与方法签名；
- 关键参数摘要；
- Java stack；
- 返回值摘要；
- 对应静态证据位置。

## 看雪查字典入口

本 reference 的主流程不依赖课程材料。只有在以下情况反复卡住时，才把看雪第1章作为补课入口：

- Frida Java Hook 基础语法、`Java.use`、`overload`、返回值包装或原实现调用不熟；
- 接口、混淆短名、Kotlin 文件类或运行时实现类导致 Hook 点总是写错；
- 调用栈能打印出来，但不知道如何把它和 JADX 静态证据对应。

优先查看：

- 看雪第1章 课时1-4：Frida Hook Java；
- workflow 顶层 `../../../references/kanxue-course-directory-index.md`。

课程材料只作为补课和脚本写法参考；真实类名、参数、返回值和调用栈仍必须来自当前 TASK 的运行时证据。
