# Paper Learning Workflow

状态：`seed / scaffold-only`

## 目标

把“读文献”升级为“学论文”：

```text
不是只摘摘要；
不是只做文献综述；
而是拆出一篇或一组论文如何提出问题、构造 gap、搭机制、设计方法、组织证据、写发现和贡献。
```

## 当前边界

本子 workflow 当前只搭架子，不预先拆分文献类型。

后续可根据真实项目逐步分化：

- 基础文献学习；
- 模板文献学习；
- 强参考文献学习；
- 方法文献学习；
- 理论文献学习；
- 数据/变量/测量文献学习；
- 目标期刊风格学习。

这些分支暂不创建，等真实学习任务暴露稳定差异后再拆。

## 最小主轴

1. 固定学习目标：
   - 为选题；
   - 为理论机制；
   - 为方法设计；
   - 为变量/数据；
   - 为结果叙事；
   - 为投稿风格；
   - 为审稿或自审。
2. 识别文献角色：
   - 这篇/这组文献在当前项目中为什么值得学；
   - 暂不强行分类 strong/weak，只记录实际用途。
3. 抽论文论证结构：
   - 必要时组合 `workflow-argument-validity`；
   - 还原核心发现、研究问题、gap、机制、方法、证据和贡献。
4. 沉淀学习问答：
   - 学论文过程中，用户常会追问“这个变量怎么来的”“这个检验怎么做”“这套写法为什么高级”“这个方法能不能迁移”；
   - 这类问答不能只留在聊天记录里，应进入项目级 `docs/learning-qa.md` 或 TASK 局部 `docs/qa.md`；
   - 每条问答至少记录：问题、简明回答、原文依据、可迁移点、不可迁移边界、后续需补材料。
5. 提取可迁移写法：
   - 引言怎么推进；
   - 理论机制怎么搭；
   - 方法和结果如何服务核心发现；
   - 贡献如何从发现上升到文献位置。
6. 对照当前项目：
   - 哪些可迁移；
   - 哪些不能迁移；
   - 哪些需要进一步检索、读全文或做案例学习。
7. 输出学习卡：
   - 供后续写论文、审稿、自审或返修调用。

## 学习问答层

学习问答层用于承载“边读边问”产生的知识。它和正式学习卡分工不同：

| 产物 | 作用 |
|---|---|
| `docs/learning-qa.md` | 保存用户追问、即时解释、原文依据和下一步补学点 |
| `outputs/paper-learning-card.md` | 提炼最终可迁移结构，不保留所有过程问答 |
| `logs/log.md` | 记录动作、路径、质量边界和 workflow/skill 反哺 |

判断一条问答是否应沉淀：

- 解释了用户不熟悉的方法、变量、数据处理或检验；
- 揭示了论文写法、论证推进或贡献上升的技巧；
- 暴露了当前底稿缺口，如 supplementary、表格视觉 QC、代码或数据说明；
- 可能迁移到当前写作、审稿或方法设计。

推荐格式：

```markdown
## YYYY-MM-DD 问答：标题

### 用户问题

### 简明回答

### 原文依据

### 可迁移点

### 不可迁移边界

### 后续需补
```

## 最小输出

```text
学习对象：
学习目标：
文献角色：
一句话核心发现：
研究问题 / gap / 机制 / 方法 / 证据 / 贡献：
学习问答摘录：
可迁移模板：
不可迁移边界：
对当前项目的启发：
下一步需要补学：
```

## 组合引擎

按需组合，不复制规则：

- `workflow-argument-validity`：抽论文论证树、检查关键箭头；
- `scholar-kit-*`：检索、补摘要、查引用和相关文献；
- `academic-field-evidence-learning`：需要建立领域地图时；
- `course-driven-skill-engineering`：从案例/课程/样本文献反哺 Skill 时。

## 完成标准

当前 scaffold 版本的完成标准很低：

- 能被 `workflow-paper` 路由；
- 能说明学习目标和输出学习卡；
- 不把 strong paper learning 过早写死为唯一模式。
