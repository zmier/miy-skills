# Node / Task 双层结构：图状研究项目的执行层与研究图层

## 背景

在 `CASE-260521-基金经理研究` 中，前期已经有数据、coauthor 讨论和一批参考文献，但还没有确定最终 paper 主干。用户指出：研究不是线性阶段推进，而更像图状探索。为了论证一个大 claim，往往需要多个子 claim、子实验和文献/数据补充；而哪个 claim 最后成为主干，常常要等期刊偏好、热点、数据可行性和初步结果共同决定。

## 关键原文认知

> Task 是线性推进的，但 TASK 产生的结果可能是非线性地贡献到不同 Node 中的。

> 图类项目，关键在于把那些 Node 节点定义出来。也就是大结构有两个文件夹：Nodes/ 和 Tasks。

## 决定

在 graph-like / hybrid graph-of-trees 的研究项目中，引入双层结构：

```text
nodes/ = 研究图层，管理长期存在的 candidate routes / claims / designs
tasks/ = 执行层，管理一段时间内线性推进的具体工作
```

一个 task 可以产生多个方向的影响：

```text
文献阅读可能更新 route gap；
数据审计可能改变 route feasibility；
实验设计可能暴露识别威胁；
coauthor 讨论可能生成新 node 或合并旧 node。
```

因此，task 不是研究主轴；node 才是图状研究项目中需要长期维护的对象。

## 最小 Node Card

每个 node 至少应记录：

```text
当前状态；
当前 claim / route 直觉；
已经明确的信息；
候选但未确认的信息；
未明确信息；
关联 tasks；
关联文献；
数据需求；
候选设计；
证据与识别威胁；
下一步问题。
```

## 迁移边界

该规则来自基金经理研究项目的 forward-test，目前可作为 `workflow-research` 0.1 beta 的结构约定。它适用于主轴尚未固定、多个候选路线并行竞争的学术研究项目；不一定适用于主流程和目标非常清晰的工序型项目。
