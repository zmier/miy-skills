# 研究项目文献阅读子 Skill

## 来源

本日志来自 `CASE-260521-基金经理研究` 的 `TASK01-coauthor-literature-to-design`。

项目已经具备一套支付宝“基金经理请回答”主数据，并收到 coauthor 在飞书文档中整理的一批参考文献。当前 task 的目标不是泛泛综述文献，而是基于这些文献与已有数据，设计第一个可推进的实验 / 研究路线。

## 用户原始困惑

用户指出：

> 还挺好的，我把相关PDF放到「/Users/narra/Documents/alib/Writer/03 Projects/260521-基金经理研究/99-文献与项目管理/PDFs/基金经理」下面了已经。那这样，我们目前主数据有了对吧，你能看到数据的link对吧？以及数据字段说明等；而本task目标，是要设计出来我们的第一个实验。要设计这个实验，就需要读文献（但是，读文献其实是个贯穿整个研究的行为，从参考实验设计、到后期要参考写作范式等）。所以，一篇文献应该对应一个文件夹对吧？0-raw-文献标题PDF原文件；1-转md-文献标题PDF转的md；2-为了完成task01而重点读并提取到的东西.md等等）。所以，我们是不是可以先写起来这个 workflow-research 的「读文献」子SKILL了？我不知道我表达的是否清晰，请帮我总结下我的困惑。这个应该是个编排型SKILL（workflow-tao），因为已经有 scholar-pdf-markdown-restoration 这类功能SKILL可以用了。

## 当时的总结

这段困惑的核心不是“要不要读 PDF”，而是：

```text
学术项目里的文献阅读不是一次性 R2 阶段；
它是贯穿 route 形成、实验设计、识别判断、变量构造、结果解释和论文写作的项目级资产生产过程。
```

因此，文献不能只被整理成一个 bibliography，也不能只被转换成 Markdown。每篇文献应逐渐形成一个可复用的 project asset：

```text
原始 PDF；
可读 / 可引用的 Markdown 底稿；
为了某个 task 或 route 做的重点提取；
变量、数据、识别和实验设计映射；
后期写作范式、表格范式和 contribution 写法；
阅读过程日志与剩余风险。
```

## 对 workflow-research 的架构含义

`workflow-research` 需要一个子 Skill：`research-literature-reader`。

它应是编排型 Skill，而不是底层 PDF 转换 Skill。它的职责是：

```text
带着当前 project / task / candidate route 去读一篇或一组文献；
判断哪些底层能力需要被调用；
把文献转化为实验设计、变量、数据需求、识别、机制、威胁和写作范式资产；
把 task-specific 阅读和 project-level 可复用资产分层保存。
```

它可以编排：

```text
scholar-pdf-markdown-restoration：PDF -> restored Markdown；
workflow-paper-learning：论文结构和写作范式学习；
workflow-argument-validity：claim / mechanism / evidence / threat 审计；
scholar-kit：文献检索、引用和元数据增强；
task-driven-project-manager：task 过程、证据和日志管理。
```

但它不替代这些功能 Skill。

## 暂定文献资产结构

迁移状态：`draft-rule`。

每篇文献可以有一个文件夹。第一版建议结构为：

```text
<paper-slug>/
├── 0-raw/
│   └── <title>.pdf
├── 1-md/
│   ├── manuscript_raw.md
│   ├── manuscript_restored.md
│   └── sections/
├── 2-task-readings/
│   └── TASK01-design-extraction.md
├── 3-route-mapping/
│   └── route-map.md
├── 4-writing-patterns/
│   └── writing-patterns.md
└── logs/
    ├── restoration-qc.md
    └── reading-log.md
```

实际项目中可以兼容已有目录，只要能保留以下层次：

```text
raw source；
restored reading substrate；
task-specific extraction；
route / claim mapping；
writing-pattern extraction；
logs / provenance。
```

## 当前暂定规则

1. 文献阅读应从当前 task / route 的问题出发，不做无目标全文摘抄。
2. PDF 转 Markdown 是底层基础设施，不等于研究阅读完成。
3. 同一篇文献可以被多次读取：TASK01 读实验设计，后续 task 读写作范式、变量构造或 robustness。
4. task-specific 产物和 project-level 资产要分层保存，避免后续复盘时不知道“当时为什么这样读”。
5. 单篇文献的阅读结论不能直接变成稳定 workflow 规则，必须经 `CASE-260521-基金经理研究` forward-test 后再提升。
