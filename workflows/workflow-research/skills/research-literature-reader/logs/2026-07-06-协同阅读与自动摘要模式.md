# 协同阅读与自动摘要模式

## 来源

本日志来自 `CASE-260521-基金经理研究` 在试读 `Shall We Talk? The Role of Interactive Investor Platforms in Corporate Communication` 时暴露出的流程问题。

当时 `research-literature-reader` 已经能处理 PDF / Markdown 底稿、文献资产结构、task-specific extraction 和 route mapping，但它默认把“读文献”理解成一种执行任务：读取材料、整理产物、写入文件。

用户指出，真实协同读文献时，用户本人还没有读过论文，不能由 Agent 直接“呼噜呼噜”往下加工。Agent 需要先在对话窗口中给出可讨论的导览卡，让用户基于该卡继续提问、纠偏和选择深读方向。

## 用户核心判断

用户确认：

```text
“协同读文献”区别于“自动文献摘要”。
```

进一步讨论后，形成结构判断：

```text
collaborative-reading 和 automatic-summary 不能平级挂在 research-literature-reader 下；
它们应属于同一个 paper-reading 父能力下面的两种执行模式。
```

确认的结构：

```text
research-literature-reader/
├── SKILL.md
├── skills/
│   └── paper-reading/
│       ├── SKILL.md
│       └── skills/
│           ├── collaborative-reading/
│           │   └── SKILL.md
│           └── automatic-summary/
│               └── SKILL.md
```

## 抽象含义

`research-literature-reader` 是项目级文献资产编排，关注：

```text
task / route / project asset / provenance / paper folder。
```

`paper-reading` 是单篇或一组文献的阅读父 Skill，关注：

```text
本轮到底怎么读；
是否对话优先；
是否文件优先；
是否先讲解再沉淀；
是否可以自动完成。
```

其下两个初始模式为：

```text
collaborative-reading：
  对话优先。先在对话窗口返回 Paper Orientation Card；
  用户追问、确认或调整重点后，再决定是否写入 task extraction / route map。

automatic-summary：
  文件优先。用户明确希望 Agent 自动读完并整理；
  可以直接产出结构化摘要、design extraction、route mapping 或 writing patterns。
```

## Paper Orientation Card

协同阅读的强制第一步不是写文件，而是在对话中返回一张可讨论的卡：

```text
一句话核心发现；
主 X；
X 的操作化 / 代理变量；
主 Y；
Y 的操作化 / 代理变量；
主机制；
文献 / 学术基础和对话；
research gap；
对当前项目的初步可迁移性；
建议下一步深读位置。
```

这张卡的作用是建立共同理解界面，而不是替代后续精读。

## 当前规则

迁移状态：`structural-upgrade / forward-test-required`。

1. `research-literature-reader` 应升级为复合 Skill 父入口。
2. `paper-reading` 应成为单篇 / 一组文献阅读的二级父 Skill。
3. `collaborative-reading` 和 `automatic-summary` 是 `paper-reading` 的模式分支，不应直接平级挂在项目级父入口下。
4. 在 collaborative-reading 模式下，默认不直接写满 `TASKxx-design-extraction.md` 或 `route-map.md`；先返回 Paper Orientation Card，并等待用户追问或确认。
5. 在 automatic-summary 模式下，可以直接写文件，但必须标明底稿状态、阅读目的和剩余风险。

