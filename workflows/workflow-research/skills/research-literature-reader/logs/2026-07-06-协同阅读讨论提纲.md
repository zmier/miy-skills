# 协同阅读讨论提纲

## 来源

本日志来自 `CASE-260521-基金经理研究` 继续试跑 `collaborative-reading` 时的讨论。

在前一轮升级中，协同阅读已经要求第一轮对话先返回 `Paper Orientation Card`。用户进一步指出，这还不够：协同阅读不能只是一轮轮漂浮的聊天，它需要一个持续维护的“讨论提纲”，让用户和 Agent 都能知道：

```text
我们准备围绕哪些问题读这篇文献；
哪些已经讨论；
哪些还没讨论；
用户提出了哪些提纲外问题；
哪些理解已经形成共识；
哪些问题仍然 pending。
```

## 用户核心判断

用户指出：

```text
协同阅读模式应该生成并维护一个讨论提纲。
整个讨论过程应该围绕并逐步完善这个文档，直到最后讨论完成。
这个讨论提纲之后也应该成为 review 入口。
```

这意味着协同阅读的主产物不是摘要，而是一个逐步演化的共同工作台。

## 讨论提纲的原则

`discussion-outline.md` 应该从 `Paper Orientation Card` 展开，但不等于它。

初始提纲至少包括：

```text
一句话核心发现；
主 X / X 的操作化；
主 Y / Y 的操作化；
主机制；
文献对话；
research gap；
识别与设计；
可迁移性；
下一步深读位置。
```

对话推进时按三类处理：

```text
提纲中有，且用户已经讨论：
  更新该条目的状态、用户问题、Agent 回答、当前共识、未解决点。

提纲中有，但用户还没讨论：
  保持 pending；不要假装已经完成；必要时提醒用户是否要继续。

提纲中没有，但用户提出了：
  先放入附录 / 新增讨论点；记录用户认知、Agent 回答和是否应提升为正式提纲项。
```

## 文件定位

建议每篇文献的协同阅读主文件为：

```text
2-task-readings/<TASKxx>-discussion-outline.md
```

或者若该讨论不是特定 task，而是通用读文献：

```text
logs/discussion-outline.md
```

该文件不同于：

```text
Paper Orientation Card：第一轮对话导览；
TASKxx-design-extraction.md：讨论稳定后沉淀的任务化提取；
route-map.md：文献与项目路线的映射；
writing-patterns.md：写作范式沉淀。
```

## 当前规则

迁移状态：`structural-upgrade / forward-test-required`。

1. collaborative-reading 模式应维护 `discussion-outline.md`。
2. 第一轮 Paper Orientation Card 后，应生成或更新讨论提纲，而不是直接进入完整 extraction。
3. 每轮对话后，若有新增理解，应更新讨论提纲状态。
4. 提纲外问题不得丢失，先进入附录，再判断是否提升为正式提纲项。
5. 很久以后 review 这篇文献时，优先从 discussion outline 恢复上下文。

