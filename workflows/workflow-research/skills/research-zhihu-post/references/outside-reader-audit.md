# Outside-Reader Audit

## 目的

用一个不了解项目目录、TASK 历史和内部术语的同行视角，检查研究解释稿是否真正自足，并利用失败项反向发现研究管理问题。

## Audit A：证据对账

先建立下表，再审正文：

| Evidence item | Current status | Current wording | Old wording | Source owner | Action |
|---|---|---|---|---|---|
| 核心经验事实 | anchor / revised / held |  |  |  |  |
| 结果发生层级 | located / unresolved |  |  |  |  |
| 候选机制 | compatible / weakened / archived |  |  |  |  |
| 因果解释 | identified / not identified |  |  |  |  |
| 下一路线 | active / queue-data / theory-boundary |  |  |  |  |

规则：

1. 旧稿中的强表述若已被新证据削弱，必须修改原段，不得只追加脚注。
2. 新证据只改变“发生在哪里”时，不得写成“为什么已经解释”。
3. 负结果应说明它削弱了哪条路线，而不是笼统写“没有结果”。
4. 分析脚本修复过口径时，使用修复后的主结果，并保留尺度和版本边界。

## Audit B：零私有上下文测试

让稿件在逻辑上脱离项目目录。逐项检查：

| Check | Pass condition |
|---|---|
| 研究对象 | 第一次出现时说明谁回答谁、观察什么行为 |
| 分析单位 | 说明是基金、份额代码、经理、季度还是投资者 |
| 时间关系 | 用“回答季度 / 下一季度”等自然语言解释 q、q+1 |
| 数据字段 | 用中文含义在前、变量名在后；变量名可省略 |
| TASK 编号 | 删除后正文仍然连贯 |
| 指代 | “这个结果”“上一轮”都有明确前件 |
| 术语 | 首次出现即定义，后文才可使用简称 |
| 私有知识 | 不依赖内部邮件、路径或口头确认才能理解 |

快速测试：随机选一段，把其中 TASK 编号和代码变量遮住。若段落失去意义，说明它仍是项目内笔记，不是外部可读稿。

## Audit C：结论阶梯

对每个“说明、支持、证明、导致、机制”句子标注层级：

```text
L1 pattern：观察到什么统计形状
L2 location：形状出现在哪个样本、单位、时间和尺度
L3 compatibility：与哪些机制相容或冲突
L4 causality：是否识别 X 导致 Y
```

红灯：

- L1 星号直接写成 L3 机制；
- 匹配、固定效应或稳健性检验直接写成 L4 因果；
- 聚合层级结果被解释为同一投资者行为；
- “没有显著增量”写成“严格为零”；
- 典型单元的对数结果写成市场绝对总量变化。

## Audit D：数字与星号

每张结果表至少能回答：

```text
比较谁和谁？
结果属于哪个时间？
单位是什么？
系数是否可直接解释成百分比？
星号阈值是什么？
未显著是方向不稳、精度不足，还是估计接近零？
```

不要比较“星号数量”来判断两个系数是否彼此不同。若要声称两组不同，报告正式差异检验。

## Audit E：公式与结果绑定

当正文含回归、匹配、分解或统计检验时，逐项检查：

| Check | Pass condition |
|---|---|
| 公式位置 | 公式紧邻它所解释的证据层，不只藏在文末 Q&A |
| 规格绑定 | 公式、结果表和正文报告的是同一主规格 |
| 稳健性区分 | 主规格与加入额外固定效应、样本限制或替代变量的规格分别命名 |
| 方法命名 | 实际是最近邻、精确匹配、倾向得分、加权还是回归，名称与代码一致 |
| 符号解释 | 观察单位、时间、$Y$、处理/比较组、控制、固定效应和聚类层级均可理解 |
| 可证伪条件 | 说明哪个系数、差值或原假设回答当前问题 |
| 变换边界 | 对数、标准化、原始量和百分比之间没有偷换 |
| 分解边界 | 原始算术恒等式与变换后的回归系数明确分开 |
| 组间差异 | 不用两组星号多少代替正式系数差或联合检验 |
| 平台渲染 | 同步后回读，LaTeX 没有因换行、转义或导入器拼接而损坏 |

随后运行“双读者复述”：同行应能从公式和结果表快速说出估计量；不看公式的普通读者也应能从紧随其后的解释说出“比较谁、为什么这样比、结论边界是什么”。任一读者只能靠猜，均判为 `revise`。

## Audit F：陌生读者复述

稿件应让陌生同行在读完前 20% 后回答：

1. 研究问题是什么？
2. 最反直觉的结果是什么？
3. 当前最强结论是什么？
4. 哪个常见解释已被削弱？
5. 最大的数据或识别限制是什么？

若不能回答，优先重写开头，不要继续增加后文。

## Audit G：公开安全

在 `peer-discussion-draft` 或 `publish-ready` 模式检查：

- 删除凭证、token、私有下载链接和绝对路径；
- 匿名化协作者和未授权机构信息；
- 不贴未批准公开的原始文本、用户记录和业务标识；
- 样本数和字段细节只保留已批准口径；
- 把“可供同行讨论”与“已获准公开发布”分开；
- 平台同步后回读公式、表格和引用。

## Audit 结果

用以下状态结束：

```text
pass：可作为目标 mode 的交付；
revise：内容基本正确，但存在陌生读者依赖或表述越级；
blocked-publication：内部审计可用，但保密或事实口径未批准公开；
reconcile-evidence-first：源证据相互冲突，必须先回 evidence owner 对账。
```
