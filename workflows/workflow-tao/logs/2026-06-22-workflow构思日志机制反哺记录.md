# 2026-06-22 Workflow 构思日志机制反哺记录

## 元信息

- 日期时间：2026-06-22
- 主题：将 `logs/YYYY-MM-DD-主题.md` 的 workflow 构思记录机制反哺到 `workflow-tao`
- 来源案例：`workflow-task-driven-project` 的分形 task-driven 升级
- 触发问题：用户询问“记录 workflow 构思过程到 logs 下面的机制，可以补充反哺到 workflow-tao 中吗”

## 原始问题

用户提出：

> 记录workflow构思过程的到logs/下面（如：「logs/2026-06-22-分形task-driven-workflow讨论记录.md」）的这个机制，可以补充反哺到 workflow-tao 中吗

## 关键观察

`workflow-tao` 已经有 provenance、project/TASK 边界、migration status 和 regression protocol，但此前没有明确规定：

```text
workflow 的构思过程本身也要保留在目标 workflow 的 logs/ 中。
```

这导致一个风险：最终 `SKILL.md` 和 `references/` 只保留稳定结论，但丢失规则来自哪里、当时有哪些方案分歧、哪些内容尚未稳定。

## 最终决定

将该机制提升为 `workflow-tao` 的通用元规则：

```text
创建或重大升级 workflow 时，
先在目标 workflow 的 logs/YYYY-MM-DD-主题.md 记录构思过程，
再把稳定规则提升到 references/templates/SKILL.md。
```

```text

references/workflow-conception-log-policy.md
references/workflow-skill-shape.md

logs/2026-06-22-workflow构思日志机制反哺记录.md
```

## 提升规则

已提升到 `workflow-tao`：

- workflow 构思日志触发条件；
- `logs/YYYY-MM-DD-主题.md` 命名规则；
- logs 与 references/templates/SKILL.md 的边界；
- 重大 workflow 创建或升级必须留 conception log；
- orchestrator 启动流程加入 conception log policy。

## 保留在个案中的内容

`workflow-task-driven-project` 的具体分形讨论原文仍保留在它自己的：

```text
workflow-task-driven-project/logs/2026-06-22-分形task-driven-workflow讨论记录.md
```

`workflow-tao` 只吸收“构思日志机制”这条元规则。
