# 外部学习提示词纳入层级判断

## 元信息

- 日期时间：2026-06-25
- 主题：小红书外部学习提示词是否应成为子 Skill
- 目标 workflow：`workflow-tao`
- 关联 Skill：`course-driven-skill-engineering`
- 来源材料：`/Users/narra/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/wxid_ivssdy1liead12_3cf9/temp/drag/中英提示词.pdf`
- 记录目的：保留一次“外部提示词样本如何进入 Skill/workflow 体系”的层级判断。

## 原始问题

用户希望判断一份从小红书获得的中英提示词 PDF，是否有必要补充到 `course-driven-skill-engineering` 中，作为子 Skill 或其他结构，并同时提到 `workflow-tao`。

## 关键观察

该 PDF 是一份 `CLAUDE.md` 风格的学习仓库规约，原始领域是 CFP 考试备考。内容包含：

- 交互式学习导师角色；
- 先询问已有理解，再讲解，再理解检测；
- 每次学习会话记录 session notes；
- 更新全局 progress tracker；
- 对税务、公式、考试答案等高风险内容强制核验；
- CFP 考纲、分值和个案示例。

其中可迁移的是学习会话治理结构；不可迁移的是 CFP 个案内容。

## 方案分歧

### 方案 A：创建子 Skill

不采纳。理由：

- 当前材料只有一个外部提示词样本；
- 没有独立执行对象、评测样本和 forward-test；
- 与 `simon-learning-card-builder`、`course-driven-skill-engineering` 的职责存在重叠；
- 过早创建子 Skill 会把“提示词风格”误当成稳定能力。

### 方案 B：直接写入 `course-driven-skill-engineering/SKILL.md`

不采纳为主方案。理由：

- 主流程已经很重；
- 该规则更像学习会话治理参考，不应改变所有 course-driven 任务默认流程；
- 其中高风险核验规则需要按领域触发，不能无条件套用。

### 方案 C：新增 reference，并保留 provenance

采纳。理由：

- 能吸收稳定结构；
- 能去除 CFP 个案固定值；
- 不污染主流程；
- 后续若多次在学习项目中复用，再考虑提升到 SKILL.md 或拆成子 Skill。

## 最终决定

新增 `course-driven-skill-engineering/references/guided-learning-session-governance.md`，作为“引导式学习会话治理”参考。

新增 `course-driven-skill-engineering/references/source-provenance.md`，记录来源、采纳、未采纳和清洗方式。

不创建子 Skill；不直接把 CFP 考纲或固定路径写入通用 Skill。

## 提升规则

已提升到 reference：

- 学习会话按“回看上下文 → 主线 TODO → 初始理解 → 聚焦讲解 → 理解检测 → 掌握/盲区 → 更新进度”推进；
- 单次会话记录与全局进度入口分工；
- 高风险事实必须核验；
- 外部提示词样本应区分可迁移结构与个案固定值。

## 保留在个案中的内容

- CFP 备考路径；
- Roth IRA 示例；
- 固定 `/sessions/`、`/progress/` 路径；
- 小红书来源本身的展示样式。
